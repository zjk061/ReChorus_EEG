## 1. 项目中该数据集的定位

当前项目基于 ReChorus 2.0 推荐系统框架改造而来，整体目标是做推荐任务。目前在该项目中，`EEGsvRec_eeg` 是重点数据集，主要用于 EEG 场景下的 CTR 预测。

也就是说，当前任务可以理解为：

> 给定一个用户、一个物品/视频，以及该用户观看该物品时的上下文信息和 EEG 特征，预测该用户对该物品是否产生正反馈，输出点击/正反馈概率。

从机器学习任务类型看，这是一个二分类 CTR 预测任务。每一行样本对应一个 `用户-物品-情境-EEG-标签` 组合。

## 3. train/dev/test 的数据格式

`train.csv`、`dev.csv`、`test.csv` 三个文件的列结构一致。

列名如下：

```text
user_id,
item_id,
time,
end_time,
c_view_duration_f,
c_session_mode_c,
c_session_id_c,
c_video_order_f,
c_video_type_c,
label,
c_interest_f,
c_immersion_f,
c_valence_f,
c_arousal_f,
c_playrate_f,
c_EEG_data_310_f
```

按照功能可以分为几类：

| 类型 | 字段 |
| --- | --- |
| 基础交互字段 | `user_id`, `item_id`, `time`, `end_time`, `label` |
| 普通情境特征 | `c_view_duration_f`, `c_session_mode_c`, `c_session_id_c`, `c_video_order_f`, `c_video_type_c`, `c_interest_f`, `c_immersion_f`, `c_valence_f`, `c_arousal_f`, `c_playrate_f` |
| EEG 特征 | `c_EEG_data_310_f` |

命名规则沿用 ReChorus 上下文特征规范：

- `u_*` 表示用户特征。
- `i_*` 表示物品特征。
- `c_*` 表示情境特征。
- 后缀 `_c` 通常表示类别型特征。
- 后缀 `_f` 通常表示连续值或浮点型特征。

## 5. train/dev/test 字段含义

### 5.1 基础字段

#### `user_id`

用户编号。当前范围是 `0-29`。

模型中该字段用于：

1. 构建用户-物品正反馈图。
2. 在 LightGCN 中索引用户 embedding。
3. 保存预测结果时标识样本所属用户。

#### `item_id`

物品/视频编号。当前最大 ID 为 2683。

模型中该字段用于：

1. 构建用户-物品正反馈图。
2. 在 LightGCN 中索引物品 embedding。
3. 保存预测结果时标识样本对应物品。

#### `time`

观看开始时间戳。

当前代码中，`time` 主要用于 `BaseReader` 读取数据后排序：

```python
sort_values(by=['user_id', 'time'])
```

它没有直接作为模型输入特征参与 `CTRLightGCNCTR.forward()` 的预测。

#### `end_time`

观看结束时间戳。

当前主模型没有显式使用 `end_time`。它更像是原始行为记录字段，可能用于计算观看时长，但目前已有 `c_view_duration_f` 字段。

#### `label`

CTR 二分类标签。

- `1`：正样本，表示点击/正反馈/有效交互。
- `0`：负样本，表示未点击/非正反馈。

当前模型输出的是点击概率，训练时用 `label` 和预测概率计算 BCE loss。

## 6. 情境特征字段含义

情境特征均以 `c_` 开头，存在于 `train.csv`、`dev.csv`、`test.csv` 中。

### 6.1 `c_view_duration_f`

观看时长，连续值。

样例中值如：

```text
15.536
12.102
30.106
```

当前 `CTRLightGCN.py` 中因为过滤条件排除了 `view` 相关特征，所以该字段虽然被 Reader 读入，但没有进入当前主模型预测分支。

### 6.2 `c_session_mode_c`

session 模式，类别型特征。

当前 `CTRLightGCN.py` 中排除了 `session` 相关特征，所以该字段没有进入当前主模型预测分支。

### 6.3 `c_session_id_c`

session 编号，类别型特征。

当前同样因 `session` 过滤条件被排除，没有进入当前主模型预测分支。

### 6.4 `c_video_order_f`

当前视频在 session 中的顺序。

当前 `CTRLightGCN.py` 中显式排除了：

```python
key != 'c_video_order_f'
```

因此它被 Reader 读入，但没有进入当前主模型预测分支。

### 6.5 `c_video_type_c`

视频类型，类别型特征。

当前该字段会进入 `CTRLightGCNCTR` 的预测分支。模型把它当作一个一维数值特征，经过：

```python
self.context_encoder = nn.Linear(1, 16)
```

投影为 16 维上下文 embedding，再进一步投影成 64 维 token 参与注意力融合。

### 6.6 `c_interest_f`

兴趣评分或兴趣状态特征。

当前会被模型使用。

处理方式：

1. 单个标量输入。
2. 经过 `context_encoder` 从 1 维映射到 16 维。
3. 再经过 `context_token_proj` 从 16 维映射到 64 维 token。
4. 参与 token gate、self-attention 和 global cross-attention 融合。

### 6.7 `c_immersion_f`

沉浸程度特征。

当前会被模型使用，处理方式同 `c_interest_f`。

### 6.8 `c_valence_f`

情绪效价特征。

一般可理解为情绪正负性或愉悦程度方向的指标。

当前会被模型使用，处理方式同 `c_interest_f`。

### 6.9 `c_arousal_f`

情绪唤醒度特征。

一般可理解为情绪激活强度、兴奋程度或唤醒水平。

当前会被模型使用，处理方式同 `c_interest_f`。

### 6.10 `c_playrate_f`

播放比例或观看完成度相关特征。

当前会被模型使用，处理方式同 `c_interest_f`。

### 6.11 `c_EEG_data_310_f`

EEG 特征，是当前数据集中最特殊也最关键的情境特征。

在 CSV 中，它是一个被双引号包起来的逗号分隔长字符串，例如：

```text
"0.5476511707377614,0.4136699642737663,..."
```

读取 CSV 后，该列先作为字符串列存在。之后 `BaseReader` 会调用：

```python
utils.eval_list_columns(self.data_df[key])
```

`utils.eval_list_columns()` 会对字符串列执行：

```python
eval(str(x))
```

由于 `c_EEG_data_310_f` 的内容是用逗号分隔的数字串，经过 `eval` 后会变成一个长度为 310 的 Python tuple/list 风格对象。后续 Dataset 合 batch 时再转成 Tensor。

统计结果显示，当前所有样本的 EEG 特征长度都等于 310。

模型中使用方式是：

```python
eeg_raw = feed_dict['c_EEG_data_310_f']  # [batch, 310]
eeg_feat = eeg_raw.view(-1, 62, 5)       # [batch, 62, 5]
eeg_emb = self.eeg_dgcnn_encoder(eeg_feat) # [batch, 16]
```

因此 310 维 EEG 特征的含义是：

```text
310 = 62 个 EEG 电极节点 * 每个电极 5 维特征
```

模型中将其 reshape 为：

```text
[batch_size, 62, 5]
```

其中：

- `batch_size`：当前 batch 中的样本数。
- `62`：EEG 电极节点数。
- `5`：每个电极上的特征维度。

从代码注释看，这 5 维特征很可能与 EEG 的 DE 特征有关。DGCNN 中的注释写到：

```python
# 根据各个电极节点之间的DE特征相似性（原始310维输入的脑电DE特征）来选择top8邻居
```

因此，当前可理解为：每个样本包含 62 个电极的 EEG 特征，每个电极有 5 个 DE 相关数值。

## 9. 数据进入项目的整体流程

当前重点模型是：

```text
CTRLightGCN.CTRLightGCNCTR
```

典型启动命令类似：

```bash
python main.py \
  --model_name CTRLightGCN \
  --model_mode CTR \
  --dataset EEGsvRec_eeg \
  --path ./data/ \
  --include_user_features 1 \
  --include_item_features 1 \
  --include_situation_features 1 \
  --lr 0.001 \
  --l2 1e-08 \
  --emb_size 64 \
  --n_layers 3 \
  --batch_size 256 \
  --loss_n BCE
```

此时动态绑定关系为：

```text
模型类：CTRLightGCN.CTRLightGCNCTR
Reader：ContextReader.ContextReader
Runner：CTRRunner.CTRRunner
```

完整数据流为：

```text
main.py
  -> 解析命令行参数
  -> 根据 model_name/model_mode 找到 CTRLightGCNCTR
  -> 根据模型声明找到 ContextReader 和 CTRRunner
  -> ContextReader 读取 train/dev/test/user_meta/item_meta
  -> 构建或加载 ContextReader_context111.pkl
  -> 实例化 CTRLightGCNCTR
  -> 为 train/dev/test 创建 Dataset
  -> Dataset._get_feed_dict() 构造单条样本
  -> collate_batch() 合并 batch
  -> Runner.train() 训练模型
  -> CTRLightGCNCTR.forward() 输出 prediction
  -> CTRModel.loss() 计算 BCE
  -> CTRRunner 评估 AUC/ACC/F1_SCORE 等指标
  -> 保存 dev/test 预测结果
```

## 10. BaseReader 如何读取数据

`BaseReader._read_data()` 会读取 `train.csv`、`dev.csv`、`test.csv`。

核心逻辑：

```python
self.data_df[key] = pd.read_csv(
    os.path.join(self.prefix, self.dataset, key + '.csv'),
    sep=self.sep
).reset_index(drop=True).sort_values(by=['user_id', 'time'])

self.data_df[key] = self.data_df[key].fillna(0)
self.data_df[key] = utils.eval_list_columns(self.data_df[key])
```

含义：

1. 读取 CSV。
2. 重置索引。
3. 按 `user_id` 和 `time` 排序。
4. 缺失值填 0。
5. 对字符串列执行 `eval`，将字符串形式的列表或 tuple 转成 Python 对象。

对于 `c_EEG_data_310_f`，这一步非常关键，因为 EEG 在 CSV 中是字符串，必须转成数值序列后才能进入模型。

## 11. BaseReader 如何构建用户点击集合

`BaseReader.__init__()` 中会构建三个集合：

- `train_clicked_set`
- `residual_clicked_set`
- `clicked_set`

其中，`train_clicked_set` 对当前 LightGCN 很重要。

代码逻辑是：

```python
for key in ['train', 'dev', 'test']:
    df = self.data_df[key]
    for uid, iid, lbl in zip(df['user_id'], df['item_id'], df['label']):
        if uid not in self.train_clicked_set:
            self.train_clicked_set[uid] = set()
            self.residual_clicked_set[uid] = set()
            self.clicked_set[uid] = set()
        if key == 'train' and lbl == 1:
            self.train_clicked_set[uid].add(iid)
        else:
            self.residual_clicked_set[uid].add(iid)
        if lbl == 1:
            self.clicked_set[uid].add(iid)
```

这说明：

- 只有训练集中 `label == 1` 的用户-物品对会进入 `train_clicked_set`。
- `train_clicked_set` 被 LightGCN 用来构建用户-物品二部图。
- 因此 LightGCN 的协同过滤图只基于训练集正反馈构建，不使用训练集负样本边，也不使用 dev/test 正样本边建图。

## 12. ContextReader 如何收集上下文特征

`ContextReader` 会根据命令行参数决定是否读取三类上下文特征：

```text

--include_item_features
--include_situation_features
```

### 12.1 用户特征

如果存在 `user_meta.csv` 且 `include_user_features == 1`：

```python
self.user_meta_df = pd.read_csv(user_meta_path, sep=self.sep)
self.user_feature_names = sorted([c for c in self.user_meta_df.columns if c[:2] == 'u_'])
```

当前用户特征名为：

```text
u_age_f
u_gender_c
u_usage_f
```

注意这里经过 `sorted()` 排序，所以顺序可能和 CSV 原始列顺序不同。

### 12.2 物品特征

如果存在 `item_meta.csv` 且 `include_item_features == 1`：

```python
self.item_meta_df = pd.read_csv(item_meta_path, sep=self.sep)
self.item_feature_names = sorted([c for c in self.item_meta_df.columns if c[:2] == 'i_'])
```

当前物品特征共 17 个 `i_*` 字段。

日志中打印 `# Item Features: 18` 是因为打印的是 `item_df.shape[1]`，其中包含了 `item_id` 这一列。因此真正的物品上下文特征数量是 17 个，不包含 `item_id`。

### 12.3 情境特征

如果 `include_situation_features == 1`：

```python
self.situation_feature_names = sorted([c for c in self.data_df['train'].columns if c[:2] == 'c_'])
```

## 13. Dataset 如何构造单条样本

当前模型继承关系是：

```python
class CTRLightGCNCTR(ContextCTRModel, LightGCNBase)
```

因此它使用 `ContextCTRModel.Dataset`，而该 Dataset 又继承 `CTRModel.Dataset`。

### 13.1 CTRModel.Dataset 的基础 feed_dict

`CTRModel.Dataset._get_feed_dict()` 对每一行构造：

```python
feed_dict = {
    'user_id': user_id,
    'item_id': [item_id],
    'label': [label]
}
```

注意：

- `user_id` 是单个数。
- `item_id` 被包成列表，即 `[item_id]`。
- `label` 被包成列表，即 `[label]`。

这说明当前 CTR 数据是一行一个用户-物品样本，而不是一行一个用户对应多个候选物品。

### 13.2 ContextCTRModel.Dataset 补充上下文特征

`ContextCTRModel.Dataset._get_feed_dict()` 会继续调用：

```python
get_context_feature(feed_dict, index, self.corpus, self.data)
```

该函数会把三类上下文补进 `feed_dict`：

1. 用户特征 `u_*`
2. 情境特征 `c_*`
3. 物品特征 `i_*`

对于物品特征，因为 `item_id` 是 `[item_id]` 这种列表形式，所以最终每个 `i_*` 特征通常会变成长度为 1 的数组。

### 13.3 batch 合并

`BaseModel.Dataset.collate_batch()` 会把多条 `feed_dict` 合成 batch。

例如 batch 后常见形状为：

```text
user_id: [batch_size]
item_id: [batch_size, 1]
label: [batch_size, 1]
c_EEG_data_310_f: [batch_size, 310]
普通 c_*: [batch_size]
```

后续 `utils.batch_to_gpu()` 会把 Tensor 移动到指定设备。

## 14. 当前模型 CTRLightGCNCTR 的整体结构

当前核心模型文件是：

```text
/root/autodl-tmp/src/models/general/CTRLightGCN.py
```

重点类：

```python
class CTRLightGCNCTR(ContextCTRModel, LightGCNBase)
```

它结合了：

- `ContextCTRModel`：负责 CTR 任务、BCE loss、上下文 Dataset。
- `LightGCNBase`：负责 LightGCN、EEG 编码、上下文编码、特征融合和预测。

模型主要由以下部分构成：

1. LightGCN 用户/物品协同过滤编码器。
2. EEG DGCNN 编码器。

5. CTR 预测层。

## 15. LightGCN 如何使用 user_id 和 item_id

LightGCN 用于学习用户和物品 ID 的协同过滤表示。

### 15.1 构建二部图

`LightGCNBase.build_adjmat()` 使用 `corpus.train_clicked_set` 构建用户-物品交互矩阵。

只使用训练集中 `label == 1` 的交互边。

二部图邻接矩阵结构为：

```text
[ 0   R  ]
[ R^T 0  ]
```

其中：

- `R` 是用户-物品正反馈交互矩阵。
- 用户和物品都是图节点。
- 边表示训练集中用户对物品有正反馈。

然后做对称归一化：

```text
D^(-1/2) A D^(-1/2)
```

### 15.2 LightGCN embedding 传播

`LGCNEncoder` 中有两个可训练参数：

```python
user_emb: [n_users, emb_size]
item_emb: [n_items, emb_size]
```

当前常见配置：

```text
emb_size = 64
n_layers = 3
```

前向传播时：

1. 拼接 user embedding 和 item embedding。
2. 使用归一化稀疏邻接矩阵做图传播。
3. 保存第 0 层到第 n 层 embedding。
4. 对所有层 embedding 求平均。
5. 再切分回 user embedding 和 item embedding。
6. 根据 batch 中的 `user_id` 和 `item_id` 取出当前样本对应向量。

最终每条样本得到：

```text
u_embed: [batch_size, 64]
i_embed: [batch_size, 64]
```

## 16. EEG 特征如何使用

当前 EEG 使用 DGCNN 编码。

### 16.1 输入格式

原始输入：

```text
c_EEG_data_310_f: [batch_size, 310]
```

模型中 reshape：

```python
eeg_feat = eeg_raw.view(-1, 62, 5)
```

得到：

```text
eeg_feat: [batch_size, 62, 5]
```

含义：

- 62 个 EEG 电极节点。
- 每个电极 5 维特征。
- 每条样本总计 310 维 EEG 特征。

### 16.2 DGCNN 动态图卷积

当前使用：

```python
self.eeg_dgcnn_encoder = EEGDGCNNEncoder(
    in_channels=5,
    hidden_channels=32,
    out_channels=16,
    k=8
)
```

DGCNN 的核心类包括：

- `DynamicalGraphConv`
- `EEGDGCNNEncoder`

处理流程：

1. 输入 `[batch, 62, 5]`。
2. 转置为 `[batch, 5, 62]`。
3. 根据当前节点特征计算电极之间的距离/相似性。
4. 每个电极节点选择 `k=8` 个近邻。
5. 构造动态图特征：`neighbor - self` 与 `self` 拼接。
6. 经过 `1x1 Conv2d + BatchNorm + ReLU`。
7. 对 k 个邻居做 max pooling。
8. 堆叠两层动态图卷积。
9. 使用全局平均池化得到 EEG 表示。

输出：

```text
eeg_emb: [batch_size, 16]
```

### 16.3 固定图 GCN 是否使用

代码中保留了 `EEGGCNEncoder`，并且也构建了全连接 EEG 图：

```python
self.eeg_edge_index = build_fully_connected_edge_index(self.eeg_num_nodes)
self.eeg_gcn_encoder = EEGGCNEncoder(...)
```

但当前 `forward()` 中实际使用的是：

```python
eeg_emb = self.eeg_dgcnn_encoder(eeg_feat)
```

因此固定图 GCN 当前不是主预测路径，更像是历史实现或对照实验保留代码。

### 16.4 k 值注意事项

当前 DGCNN 的 `k=8` 是硬编码：

```python
self.eeg_dgcnn_encoder = EEGDGCNNEncoder(..., k=8)
```

虽然项目里有一些围绕 DGCNN k 值的脚本和文档，例如：

```text
README_k_analysis.md
quick_k_test.py
diagnose_k_issue.py
hyperparameter_analysis.py
k_experiment_config.py
```

但当前主模型文件里还没有把 `k` 完整接入命令行参数。因此如果后续要系统做 k 值实验，需要把 `dgcnn_k` 加入模型参数解析和初始化逻辑。

## 17. 普通情境特征如何使用

除 EEG 之外，当前模型会筛选部分 `c_*` 情境特征。

代码逻辑：

```python
for key in feed_dict:
    if key[:2] == 'c_' \
       and key[2:5] != 'EEG' \
       and key[2:9] != 'session' \
       and key[2:6] != 'view' \
       and key != 'c_video_order_f':
        context2d = feed_dict[key].unsqueeze(1)
        context16 = self.context_encoder(context2d.float())
        self.context_emb.append(context16)
```

这个条件表示：

必须满足：

- 字段名以 `c_` 开头。

同时排除：

- EEG 特征：`c_EEG_data_310_f`
- session 相关特征：`c_session_mode_c`, `c_session_id_c`
- view 相关特征：`c_view_duration_f`
- 视频顺序特征：`c_video_order_f`

因此当前实际保留下来的普通情境特征是：

```text

c_immersion_f
c_interest_f
c_playrate_f
c_valence_f
c_video_type_c
```

共 6 个。

每个普通情境特征都是标量，处理方式是：

```python
self.context_encoder = nn.Linear(1, 16)
```

也就是每个特征：

```text
[batch_size] -> [batch_size, 1] -> [batch_size, 16]
```

然后作为一个单独的 context embedding，进入后续 token attention 融合。

## 19. 多粒度注意力融合方式

当前 `CTRLightGCN.py` 中已经不再使用早期简单的拼接后全连接预测方式，而是使用 token attention 融合。

虽然代码里仍然构造了：

```python
combined = torch.cat([u_embed, i_embed, eeg_emb], dim=-1)
for feature in self.context_emb:
    combined = torch.cat([combined, feature], dim=-1)
```

但最终预测没有使用旧的：

```python
self.fc(combined)
```

当前真正使用的是 token attention 分支。

### 19.1 token 化

不同来源特征先被投影到统一的 64 维 token 空间：

```python
self.token_dim = 64
self.user_token_proj = nn.Linear(64, self.token_dim)
self.item_token_proj = nn.Linear(64, self.token_dim)
self.eeg_token_proj = nn.Linear(16, self.token_dim)
self.context_token_proj = nn.Linear(16, self.token_dim)
```

对应关系：

| 输入 | 原始维度 | token 维度 |
| --- | ---: | ---: |
| user embedding | 64 | 64 |
| item embedding | 64 | 64 |
| EEG embedding | 16 | 64 |
| 每个 context embedding | 16 | 64 |

如果当前使用 6 个普通情境特征，则每条样本 token 数量为：

```text
1 user token
+ 1 item token
+ 1 EEG token
+ 6 context tokens
= 9 tokens
```

### 19.2 token gate

每个 token 经过门控网络，得到一个 0 到 1 的权重：

```python
token_gates = self.token_gate(tokens)
tokens = tokens * token_gates
```

作用是让模型动态判断当前样本中哪些特征 token 更重要。

### 19.3 self-attention

所有 token 之间做多头自注意力：

```python
attn_output, _ = self.self_attn(tokens, tokens, tokens)
tokens = self.norm_tokens(tokens + attn_output)
```

作用是建模不同特征之间的交互关系，例如：

- 用户偏好和物品表示之间的关系。
- EEG 状态和兴趣/沉浸/唤醒度之间的关系。
- 视频类型和当前 EEG 状态之间的关系。

### 19.4 global token cross-attention

模型定义了一个可学习全局 token：

```python
self.global_token = nn.Parameter(torch.randn(1, 1, self.token_dim))
```

前向传播时，该全局 token 作为 query，对所有特征 token 做 cross-attention：

```python
global_token = self.global_token.expand(batch_size, -1, -1)
global_attn_output, _ = self.cross_attn(global_token, tokens, tokens)
global_token = self.norm_global(global_token + global_attn_output)
```

作用是从所有特征 token 中汇聚出一个全局样本表示。

### 19.5 FFN 和预测

全局 token 经过 FFN：

```python
ffn_output = self.ffn(global_token)
global_token = self.norm_ffn(global_token + ffn_output)
```

然后预测：

```python
fused_feat = global_token.squeeze(1)
prediction = self.predictor(fused_feat).squeeze(-1)
```

`CTRLightGCNCTR.forward()` 最后会做：

```python
out_dict['prediction'] = out_dict['prediction'].view(-1).sigmoid()
out_dict['label'] = feed_dict['label'].view(-1)
```

最终输出是：

```text
prediction: [batch_size]
label: [batch_size]
```

其中 `prediction` 是点击/正反馈概率。

## 20. loss 与评估指标

当前 CTR 任务使用 `CTRModel.loss()`。

默认损失函数：

```text
BCE
```

代码逻辑：

```python
loss = self.loss_fn(out_dict['prediction'], out_dict['label'].float())
```

其中：

- `prediction` 是 sigmoid 后的概率。
- `label` 是 0/1 标签。

评估由 `CTRRunner` 完成。

默认情况下，如果命令行没有指定合适的 CTR 指标，`CTRRunner` 会把原本 Top-K 默认指标替换为：

```text
AUC
ACC
F1_SCORE
```

各指标含义：

- `AUC`：ROC AUC，用预测概率评估排序/区分能力。
- `ACC`：以 0.5 为阈值的准确率。
- `F1_SCORE`：以 0.5 为阈值的 F1 分数。
- `LOG_LOSS`：代码支持，但默认指标里不一定包含。

## 23. 当前实现中的重要注意点

### 23.1 用户和物品元特征读入了，但主模型没用

这是当前最容易误解的一点。

命令行中即使设置：

```bash
--include_user_features 1
--include_item_features 1
```

`ContextReader` 也确实会读取 `user_meta.csv` 和 `item_meta.csv`，并把 `u_*`、`i_*` 放入 `feed_dict`。

但是当前 `CTRLightGCN.py` 的 `forward()` 主分支只处理符合条件的 `c_*` 特征。

因此当前模型实际没有使用用户元特征和物品元特征。

如果后续实验设计要求“使用用户特征/物品特征”，需要补充对应的编码和融合逻辑。

### 23.2 部分情境特征被显式排除

当前被排除的情境特征：

```text
c_view_duration_f
c_session_mode_c
c_session_id_c
c_video_order_f
```

这不是 Reader 没有读，而是模型 forward 中主动过滤掉了。

如果后续要做消融实验或完整上下文实验，需要明确这些特征是否应该加入。

### 23.3 EEG 当前一定会被使用

当前 `LightGCNBase.forward()` 中直接访问：

```python
feed_dict['c_EEG_data_310_f']
```

因此只要使用当前 `CTRLightGCNCTR`，数据中必须有 `c_EEG_data_310_f`，且每条样本必须能 reshape 成 `[62, 5]`。

也就是说，每条 EEG 特征长度必须是 310。

### 23.4 DGCNN k 值尚未参数化

当前 `k=8` 硬编码在模型初始化中。如果要做严谨的 k 值实验，建议将其改为命令行参数。

### 23.5 `combined` 变量目前基本是遗留逻辑

当前 forward 中仍然构造了 `combined`，但实际预测走的是 token attention 分支。

除非后续重新启用 `self.fc(combined)`，否则 `combined` 对最终输出没有贡献。

### 23.6 `utils.eval_list_columns()` 使用 eval

当前读取 EEG 字符串依赖：

```python
eval(str(x))
```

这对当前受控 CSV 数据能工作，但从工程安全性和鲁棒性看，`eval` 不是最理想的解析方式。如果未来数据来源不完全可信，建议改为更安全的解析方式，例如：

```python
ast.literal_eval
```

或针对逗号分隔浮点串显式解析。

## 24. 当前数据使用方式总结

当前项目对 `EEGsvRec_eeg` 的使用可以概括为：

1. `train/dev/test` 中每一行是一条 CTR 样本。
2. `label` 是二分类目标。
3. `BaseReader` 读取 CSV，按 `user_id,time` 排序，并把 EEG 字符串解析成 310 维数值序列。
4. `ContextReader` 收集 `u_*`、`i_*`、`c_*` 特征，并根据命令行参数决定是否读入。
5. `CTRModel.Dataset` 把每行变成基础 `feed_dict`：`user_id`、`item_id`、`label`。
6. `ContextCTRModel.Dataset` 把用户、物品、情境特征补进 `feed_dict`。
7. LightGCN 使用训练集中 `label == 1` 的边构建用户-物品二部图，学习 64 维用户和物品协同过滤 embedding。
8. EEG 310 维特征 reshape 成 `[62,5]`，经 DGCNN 编码成 16 维 EEG embedding。
9. 当前实际使用 6 个普通情境特征：`arousal`、`immersion`、`interest`、`playrate`、`valence`、`video_type`，每个映射成 16 维。
10. user、item、EEG、context embedding 分别投影成 64 维 token。
11. token 经过 gate、self-attention、global cross-attention 和 FFN 融合。
12. predictor 输出点击概率。
13. BCE loss 训练。
14. CTRRunner 使用 AUC、ACC、F1_SCORE 等指标评估。

## 25. 一句话理解

当前 `EEGsvRec_eeg` 数据集是一份带 EEG 和观看上下文的 CTR 二分类数据。项目用 LightGCN 从 `user_id/item_id` 学协同过滤表示，用 DGCNN 从 310 维 EEG 中学习 62 个电极之间的动态图关系，再融合部分情境特征，最终预测用户对物品的点击/正反馈概率。虽然用户元特征和物品元特征已经能被 Reader 读入，但当前 `CTRLightGCNCTR` 主预测分支并没有实际使用它们。
