# 新数据组织使用方案：严格前置 CTR 数据

本文档记录当前暂定的数据组织与使用方案。该方案用于解决原始 `EEGsvRec_eeg` 数据使用方式中的特征穿越问题，同时为后续引入 Transformer 等序列模型结构保留足够的信息。

本文档只讨论样本数据如何组织和使用；模型结构如何改造以适配新数据格式，后续单独规划。

## 1. 问题背景

当前原始样本中包含多类“观看当前短视频时或观看结束后才能获得”的字段，例如：

```text
c_EEG_data_310_f
c_interest_f
c_immersion_f
c_valence_f
c_arousal_f
c_playrate_f
c_view_duration_f
end_time
```

这些字段的含义是：

- `c_EEG_data_310_f`：用户观看当前短视频时采集到的 310 维 EEG 脑电特征。
- `c_interest_f`：用户观看当前短视频后填写问卷得到的兴趣评分。
- `c_immersion_f`：用户观看当前短视频后填写问卷得到的沉浸评分。
- `c_valence_f`：用户观看当前短视频后填写问卷得到的情绪效价评分。
- `c_arousal_f`：用户观看当前短视频后填写问卷得到的情绪唤醒度评分。
- `c_playrate_f`：用户观看当前短视频后的播放比例或完成度。
- `c_view_duration_f`：用户观看当前短视频的观看时长。
- `end_time`：当前观看行为结束时间。

如果把这些字段直接作为当前样本输入来预测当前样本的 `label`，就相当于使用未来才能知道的信息预测当前反馈，构成严重的特征穿越。

新的方案必须遵循一个原则：

> 对每一条当前样本，只允许使用推荐当前 item 之前已经可获得的信息。

## 2. 新任务定义

新的严格前置 CTR 任务定义为：

> 在推荐当前 `item_id` 给当前 `user_id` 之前，使用用户静态元特征、当前候选物品静态元特征，以及该用户过去已经完成的交互序列，预测当前样本的 `label`。

每条样本仍然是一个 CTR 二分类样本：

```text
(user_id, item_id, time) -> label
```

但当前样本中不能直接使用当前 item 观看过程中或观看后才产生的信息。

## 3. 对当前意见的客观评判

### 3.1 暂不使用 session/order 特征是合理的

当前暂定先不使用：

```text
c_session_mode_c
c_session_id_c
c_video_order_f
```

理由是：

- 它们虽然有可能在推荐前可知，但语义不够稳定。
- `c_video_order_f` 可能和推荐策略、曝光位置、观看流程强耦合。
- 当前阶段先排除它们，可以降低潜在泄露风险，使实验定义更干净。

因此，新方案中这三类特征不作为当前样本输入。

### 3.2 使用原始历史交互序列优于历史均值

为了避免特征穿越，同时保留 EEG 和情绪自评分的研究价值，新方案不采用“对历史 EEG 或历史情绪评分取均值”的方式构造历史统计特征。

相反，每条样本直接携带该用户在当前样本之前的原始历史交互记录序列。

这种方式更合适，原因是：

- 均值会丢失历史交互顺序。
- 均值会丢失用户近期状态变化。
- 均值无法表达不同历史 item 对当前推荐的差异影响。
- EEG 和情绪状态具有动态变化特征，原始序列比静态统计量更有表达力。
- 原始序列天然适合后续引入 Transformer、GRU、DIN、DIEN、SASRec 等序列模型。

### 3.3 历史记录中暂定只使用 item、EEG、四类情绪评分

对于每一条历史交互记录，暂定只引入以下字段：

```text
item_id
c_EEG_data_310_f
c_interest_f
c_immersion_f
c_valence_f
c_arousal_f
```

即每条历史记录包含：

- 历史观看过的 item ID。
- 历史观看该 item 时采集到的 EEG。
- 历史观看该 item 后得到的兴趣评分。
- 历史观看该 item 后得到的沉浸评分。
- 历史观看该 item 后得到的效价评分。
- 历史观看该 item 后得到的唤醒度评分。

这些字段如果来自当前样本，会造成特征穿越；但如果来自当前样本之前已经发生的历史样本，则在预测当前 item 时已经可知，可以作为合法历史信息使用。

### 3.4 用户和物品元特征必须引入

当前样本的 EEG 和问卷评分不再作为当前输入后，模型需要更多推荐前可知的信息。因此，引入用户元特征和物品元特征是必要的。

用户元特征来自 `user_meta.csv`：

```text
u_gender_c
u_age_f
u_usage_f
```

物品元特征来自 `item_meta.csv`：

```text
i_music_tempo_f
i_count_f
i_height_c
i_width_c
i_brightness_f
i_dif_brightness_f
i_E_2D_f
i_dif_E_2D_f
i_contrast_f
i_laplace_var_f
i_color_cast_f
i_hue_f
i_dif_hue_f
i_saturation_f
i_dif_saturation_f
i_value_f
i_dif_value_f
```

这些特征在推荐当前 item 之前已经可获得，不会造成当前样本特征穿越。

## 4. 当前样本字段使用规则

### 4.1 当前样本保留基础字段

每条当前样本保留：

```text
user_id
item_id
time
label
```

含义：

- `user_id`：当前用户。
- `item_id`：当前候选短视频。
- `time`：当前样本发生时间，用于排序和构造历史序列。
- `label`：当前样本预测目标。

### 4.2 当前样本引入用户元特征

每条样本根据 `user_id` 关联用户元特征：

```text
u_gender_c
u_age_f
u_usage_f
```

### 4.3 当前样本引入物品元特征

每条样本根据 `item_id` 关联物品元特征：

```text
i_music_tempo_f
i_count_f
i_height_c
i_width_c
i_brightness_f
i_dif_brightness_f
i_E_2D_f
i_dif_E_2D_f
i_contrast_f
i_laplace_var_f
i_color_cast_f
i_hue_f
i_dif_hue_f
i_saturation_f
i_dif_saturation_f
i_value_f
i_dif_value_f
```

### 4.4 当前样本可选保留字段

当前可考虑保留：

```text
c_video_type_c
```

前提是它是当前 item 的推荐前可知属性，例如视频类型或物品内容类别。如果后续确认该字段来自观看后标注、后处理结果，或与用户观看反馈有关，则应移除。

### 4.5 当前样本禁止直接输入字段

当前样本禁止直接使用以下字段作为当前输入：

```text
c_EEG_data_310_f
c_interest_f
c_immersion_f
c_valence_f
c_arousal_f
c_playrate_f
c_view_duration_f
end_time
c_session_mode_c
c_session_id_c
c_video_order_f
```

其中，当前样本的 EEG 和四类情绪自评分不会被丢弃，而是会在后续样本中作为历史序列的一部分出现。

## 5. 历史交互序列组织方式

### 5.1 核心规则

对每个用户单独按 `time` 升序排序：

```text
r1, r2, r3, ..., rt, ...
```

对于第 `t` 条当前样本 `rt`，其历史只能包含：

```text
r1, r2, ..., r(t-1)
```

不能包含：

```text
rt 本身
r(t+1), r(t+2), ...
```

即：

```text
history(rt) = [r1, r2, ..., r(t-1)]
```

这个规则是避免当前样本特征穿越和未来信息泄露的核心。

### 5.2 历史字段设计

建议新增以下历史序列字段：

```text
history_item_id
history_eeg_310
history_interest
history_immersion
history_valence
history_arousal
history_length
```

字段含义：

- `history_item_id`：历史观看过的 item ID 序列。
- `history_eeg_310`：每个历史 item 对应的 310 维 EEG 特征序列。
- `history_interest`：每个历史 item 观看后的兴趣评分序列。
- `history_immersion`：每个历史 item 观看后的沉浸评分序列。
- `history_valence`：每个历史 item 观看后的效价评分序列。
- `history_arousal`：每个历史 item 观看后的唤醒度评分序列。
- `history_length`：当前样本实际历史长度。

### 5.3 样本示意

假设某个用户的交互序列为：

```text
r1, r2, r3, r4
```

对于当前样本 `r4`：

```text
user_id = r4.user_id
item_id = r4.item_id
time = r4.time
label = r4.label
```

其历史为：

```text
history_item_id = [r1.item_id, r2.item_id, r3.item_id]
history_eeg_310 = [r1.eeg, r2.eeg, r3.eeg]
history_interest = [r1.interest, r2.interest, r3.interest]
history_immersion = [r1.immersion, r2.immersion, r3.immersion]
history_valence = [r1.valence, r2.valence, r3.valence]
history_arousal = [r1.arousal, r2.arousal, r3.arousal]
history_length = 3
```

对于该用户的第一条样本 `r1`：

```text
history_item_id = []
history_eeg_310 = []
history_interest = []
history_immersion = []
history_valence = []
history_arousal = []
history_length = 0
```

- `history_eeg_310` 是二维序列，每个历史记录对应一个长度为 310 的 EEG 向量。

## 7. 历史序列字段存储格式建议

当前项目的 `BaseReader` 会通过 `utils.eval_list_columns()` 将字符串列解析为 Python 对象，因此历史序列字段可以用 Python list 风格字符串存储。

### 7.1 history_item_id

示例：

```text
[12, 35, 87]
```

### 7.2 一维历史评分序列

例如 `history_interest`：

```text
[1, 4, 3]
```

或：

```text
[1.0, 4.0, 3.0]
```

### 7.3 history_eeg_310

`history_eeg_310` 是二维结构：

```text
[
  [0.1, 0.2, ..., 0.310],
  [0.3, 0.4, ..., 0.510],
  [0.5, 0.6, ..., 0.710]
]
```

每个内部列表长度必须为 310。如果当前样本没有历史，则为：

```text
[]
```

### 7.4 解析安全注意事项

如果继续依赖 `eval_list_columns()`，需要保证 CSV 中的历史序列字符串是合法 Python 表达式。

后续为了工程安全，建议将 `eval` 替换为更安全的解析方式，例如：

```python
ast.literal_eval
```

## 8. 严格避免特征穿越的构造算法

构造新样本时，应按用户分组并按时间排序。

伪代码：

```python
for user_id, user_df in df.groupby('user_id'):
    user_df = user_df.sort_values('time')
    history = []

    for row in user_df:
        new_row = build_current_sample(row, history)

        current_history_record = {
            'item_id': row['item_id'],
            'eeg_310': row['c_EEG_data_310_f'],
            'interest': row['c_interest_f'],
            'immersion': row['c_immersion_f'],
            'valence': row['c_valence_f'],
            'arousal': row['c_arousal_f'],
        }

        history.append(current_history_record)
```

关键点：

```text
必须先用已有 history 构造当前样本，再把当前样本追加到 history。
```

如果先追加当前样本，再构造当前样本的历史，就会把当前样本自身放入自己的历史，造成泄露。

## 9. 空历史样本处理

每个用户的第一条样本没有历史。建议保留这类样本，并设置：

```text
history_item_id = []
history_eeg_310 = []
history_interest = []
history_immersion = []
history_valence = []
history_arousal = []
history_length = 0
```

保留原因：

- 真实推荐系统中也存在冷启动或历史不足场景。
- 模型仍可依靠用户元特征、物品元特征和当前 item 信息预测。
- 后续序列模型可以通过 padding mask 区分空历史。

如果后续只关注有历史状态建模，也可以额外构造一个过滤掉 `history_length == 0` 的版本作为对比实验。

## 10. 历史长度处理

数据组织阶段建议保留完整历史序列，不提前截断。

原因：

- 原始完整历史最灵活。
- 后续模型可以自行决定最大历史长度。
- 方便比较不同历史窗口长度。

后续模型训练时可以设置不同窗口，例如：

```text
max_history_len = 20
max_history_len = 50
max_history_len = 100
```

并采用最近 `max_history_len` 条历史记录。这属于后续模型适配问题，当前数据方案只要求原始历史序列组织正确。

## 12. 方案优点

### 12.1 严格避免当前样本特征穿越

当前样本观看后才产生的 EEG、问卷评分、播放比例、观看时长都不再用于预测当前样本，模型输入与真实推荐前可获得的信息更一致。

### 12.2 保留 EEG 和情绪自评分的研究价值

EEG 和情绪自评分没有被丢弃，而是转化为用户历史序列信息。模型后续可以研究：

- 用户过去 EEG 状态对当前推荐反馈的影响。
- 用户过去情绪状态变化对当前偏好的影响。
- 历史 item、历史 EEG、历史情绪之间的动态关系。

### 12.3 比历史均值保留更多信息

原始历史序列保留了：

- 历史 item 顺序。
- 历史 EEG 状态变化。
- 历史情绪评分动态。
- 不同历史 item 对当前推荐的潜在影响。
- 后续引入 Transformer 序列建模的空间。

### 12.4 适合后续序列模型

该数据组织方式天然适合后续引入：

```text
Transformer
GRU
DIN
DIEN
SASRec
注意力序列模型
```

## 13. 方案代价

### 13.1 数据读取和 batch 组织更复杂

历史字段是变长序列，后续需要处理：

```text
padding
mask
history_length
batch 内不同历史长度
```

### 13.2 当前模型不能直接适配

当前 `CTRLightGCN.py` 假设 EEG 是当前样本的：

```text
[batch_size, 310]
```

新方案下 EEG 会变成历史序列：

```text
[batch_size, history_len, 310]
```

或 reshape 后：

```text
[batch_size, history_len, 62, 5]
```

因此当前模型结构后续需要调整，才能使用新的历史 EEG 序列。

### 13.3 历史较长时计算开销更大

如果保留完整历史，部分用户历史较长，后续模型训练时可能增加显存和计算开销。可以在模型阶段通过 `max_history_len` 控制。

### 13.4 空历史样本需要特殊处理

`history_length = 0` 的样本需要模型支持 padding mask 或冷启动分支，否则需要过滤。

```

用于检验历史 EEG 状态是否能提升当前推荐预测。

```

用于检验历史情绪自评分是否能提升当前推荐预测。

使用完整历史序列：

```text
history_item_id
history_eeg_310

history_immersion
history_valence
history_arousal
```

用于评估完整历史状态建模的最终效果。

## 15. 一句话总结

新的严格前置 CTR 数据方案是：当前样本只使用推荐前可知的用户元特征、物品元特征和候选 item 信息，不再直接使用当前样本观看后产生的 EEG、问卷评分、播放比例和观看时长；同时，把当前样本之前已经发生的历史交互原封不动地组织为变长历史序列，每条历史记录包含 `item_id`、EEG 和四类情绪自评分，为后续引入 Transformer 等序列模型提供数据基础。
