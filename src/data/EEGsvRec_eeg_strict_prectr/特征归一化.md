# Strict Pre-CTR 特征归一化方案

本文档记录 `EEGsvRec_eeg_strict_prectr` 数据集在 v1 模型中建议采用的特征归一化方案。

该方案面向严格前置 CTR 任务：

```text
/root/autodl-tmp/src/data/EEGsvRec_eeg_strict_prectr/
```

核心原则是：

> 只使用新版 `train.csv` 统计归一化参数，然后将同一套参数应用到 `train/dev/test`，避免 dev/test 分布信息泄露到训练阶段。

## 1. 为什么需要归一化

v1 模型会同时使用用户元特征、物品元特征、候选 item 类型、历史 item、历史 EEG、历史情绪评分等多类特征。

这些特征的数值尺度差异很大。原始样例中可以看到：

```text
i_laplace_var_f = 10300.66573
i_count_f       = 1192
i_height_c      = 1024
i_width_c       = 576
i_brightness_f  = 104.1538002
i_color_cast_f  = 0.938259236
i_dif_E_2D_f    = 0.019739932
u_age_f         = 23
u_usage_f       = 4
history EEG     大多在 0.x 范围
history emotion 约为 1-5 评分
```

如果这些连续值直接拼接后送入 MLP、DIN attention、GRU 或 Transformer，大尺度字段会天然产生更大的激活和梯度。例如 `i_laplace_var_f` 和 `i_count_f` 可能在训练初期主导模型更新，使 EEG、情绪评分、色彩差分等小尺度特征被淹没。

因此，归一化的目的包括：

- 减少不同连续特征之间的尺度差异。
- 避免大数值字段主导训练。
- 提高 MLP 和 attention 模块的训练稳定性。
- 让不同模态特征在融合前处于相近数值范围。
- 降低小数据集场景下由异常尺度带来的过拟合风险。

## 2. 总体原则

### 2.1 原始 CSV 不直接覆盖

建议保留原始 `train/dev/test.csv`、`item_meta.csv`、`user_meta.csv` 不变。

归一化优先在以下位置之一完成：

1. `StrictPreCTRReader` 读取特征后进行归一化。
2. v1 模型内部对连续特征做标准化或 normalization layer。

更推荐第一版在 Reader 侧加载固定统计量并归一化，这样模型输入清晰，也便于复现实验。

### 2.2 统计量只来自 train split

归一化统计量只从新版 strict pre-CTR 的 `train.csv` 相关样本中计算。

不使用 `dev.csv` 或 `test.csv` 统计 mean/std/min/max。

建议将统计量保存为：

```text
/root/autodl-tmp/src/data/EEGsvRec_eeg_strict_prectr/normalization_stats.json
```

训练、验证、测试时都读取同一个 `normalization_stats.json`。

### 2.3 padding 不参与统计和聚合

历史序列字段是变长序列，batch 内会 padding。

所有历史特征统计和模型聚合都必须只基于有效历史位置：

```text
valid position: position < history_length
padding:        position >= history_length
```

padding 出来的 0 不能参与：

- EEG mean/std 统计。
- 情绪评分统计。
- mean pooling。
- DIN attention。
- Transformer attention。
- GRU 最后有效状态选择。

## 3. 特征分组

### 3.1 不归一化，使用 embedding 的特征

以下特征是 ID 或类别特征，不做数值归一化：

```text
user_id
item_id
history_item_id
c_video_type_c
u_gender_c
```

建议处理方式：

```text
user_id         -> Embedding
item_id         -> Embedding
history_item_id -> Embedding
c_video_type_c  -> Embedding
u_gender_c      -> Embedding
```

注意：如果后续决定弱化或移除 `user_id` embedding，该字段仍不应作为连续数值输入。

### 3.2 需要归一化的用户连续特征

用户元特征包括：

```text
u_gender_c
u_age_f
u_usage_f
```

其中：

- `u_gender_c` 是类别特征，使用 embedding。
- `u_age_f` 是连续年龄特征，需要归一化。
- `u_usage_f` 已确认为连续使用强度，需要归一化。

建议：

```text
u_age_f   -> z-score
u_usage_f -> z-score
```

公式：

```text
x_norm = (x - train_mean) / (train_std + 1e-8)
```

统计范围：

```text
新版 train.csv 中出现过的 user_id 对应的 user_meta 记录
```

### 3.3 需要归一化的物品连续特征

物品元特征包括：

```text
i_music_tempo_f
i_count_f
i_height_c
i_width_c
i_brightness_f
i_dif_brightness_f
i_E_2D_f
i_dif_E_2D_f
i_contrast_f
i_laplace_var_f
i_color_cast_f
i_hue_f
i_dif_hue_f
i_saturation_f
i_dif_saturation_f
i_value_f
i_dif_value_f
```

这些字段建议全部作为连续数值特征处理并归一化。

其中 `i_height_c` 和 `i_width_c` 虽然后缀是 `_c`，但实际样例是分辨率数值，例如：

```text
i_height_c = 1024
i_width_c  = 576
```

第一版建议仍按连续特征归一化。后续如果确认它们只有少数固定取值，也可以改为类别 embedding 做对照实验。

#### 3.3.1 长尾大尺度特征

以下字段数值可能很大或长尾明显：

```text
i_count_f
i_laplace_var_f
```

建议先做：

```text
x_log = log1p(x)
```

再做 z-score：

```text
x_norm = (x_log - train_mean_log) / (train_std_log + 1e-8)
```

原因：

- `i_count_f` 样例值为 `1192`。
- `i_laplace_var_f` 样例值为 `10300.66573`。
- 直接 z-score 可能仍受极端值影响较大。
- `log1p` 可以压缩长尾分布。

#### 3.3.2 其他 item_meta 连续特征

除 `i_count_f` 和 `i_laplace_var_f` 外，其他 `i_*` 连续特征建议直接 z-score：

```text
x_norm = (x - train_mean) / (train_std + 1e-8)
```

统计范围：

```text
新版 train.csv 中出现过的 item_id 对应的 item_meta 记录
```

### 3.4 历史 EEG 特征

历史 EEG 字段：

```text
history_eeg_310
```

输入形状语义：

```text
[batch_size, history_len, 310]
```

建议第一版采用按维度 z-score：

```text
eeg_mean: [310]
eeg_std:  [310]
history_eeg_norm[..., d] = (history_eeg_310[..., d] - eeg_mean[d]) / (eeg_std[d] + 1e-8)
```

统计范围：

```text
新版 train.csv 中所有有效历史位置的 history_eeg_310
```

注意：

- 只统计 `history_length` 覆盖到的有效历史 step。
- 空历史样本不贡献 EEG 统计。
- padding 位置不参与统计。
- padding 位置归一化后的值在模型聚合时仍必须被 mask 掉。

如果第一版实现想更简单，也可以在 EEG encoder 前使用：

```text
LayerNorm(310)
```

但更推荐保存 train 统计量做固定 z-score，实验定义更清晰。

### 3.5 历史情绪评分

历史情绪字段：

```text
history_interest
history_immersion
history_valence
history_arousal
```

每个历史 step 可以拼成：

```text
[interest, immersion, valence, arousal]
```

如果确认评分范围是 `1-5`，建议固定缩放到 `[0, 1]`：

```text
x_norm = (x - 1) / 4
```

优点：

- 简单稳定。
- 不依赖样本统计。
- 保留评分的相对等级含义。
- train/dev/test 使用同一固定变换，不存在统计泄露。

如果后续确认评分范围不是 `1-5`，再改为使用 train split 的 z-score。

注意：

- 只处理有效历史位置。
- padding 位置不参与 pooling/attention。

## 4. normalization_stats.json 建议结构

建议统计文件结构如下：

```json
{
  "user_continuous": {
    "u_age_f": {
      "method": "zscore",
      "mean": 0.0,
      "std": 1.0
    },
    "u_usage_f": {
      "method": "zscore",
      "mean": 0.0,
      "std": 1.0
    }
  },
  "item_continuous": {
    "i_count_f": {
      "method": "log1p_zscore",
      "mean": 0.0,
      "std": 1.0
    },
    "i_laplace_var_f": {
      "method": "log1p_zscore",
      "mean": 0.0,
      "std": 1.0
    },
    "other_i_feature": {
      "method": "zscore",
      "mean": 0.0,
      "std": 1.0
    }
  },
  "history_eeg_310": {
    "method": "per_dim_zscore",
    "mean": [0.0],
    "std": [1.0]
  },
  "history_emotion": {
    "method": "fixed_minmax_1_5",
    "min": 1.0,
    "max": 5.0
  }
}
```

实际文件中：

- `history_eeg_310.mean` 长度应为 310。
- `history_eeg_310.std` 长度应为 310。
- 所有 `std` 小于极小值时应替换为 1，避免除零。

## 5. 推荐实现位置

### 5.1 统计脚本

建议新增脚本：

```text
/root/autodl-tmp/src/data/EEGsvRec_eeg/build_normalization_stats.py
```

职责：

1. 读取新版 strict pre-CTR 的 `train.csv`。
2. 读取 `user_meta.csv` 和 `item_meta.csv`。
3. 根据 train 中出现的 `user_id` 统计用户连续特征。
4. 根据 train 中出现的 `item_id` 统计物品连续特征。
5. 解析 train 中有效历史位置的 `history_eeg_310`。
6. 写出 `normalization_stats.json`。

### 5.2 Reader 侧归一化

建议在 `StrictPreCTRReader` 或后续 v1 专用 Reader 中：

1. 加载 `normalization_stats.json`。
2. 在构造 `feed_dict` 前或加入 `feed_dict` 时，对连续特征做归一化。
3. 类别特征保持原始整数 ID，交给模型 embedding。

优点：

- 模型输入已经是稳定尺度。
- 多个 v1 模型可以复用同一套 Reader。
- 便于 Mean/DIN/GRU/Transformer 多模型对照。

### 5.3 模型侧注意事项

即使 Reader 侧已经做归一化，模型侧仍建议保留：

```text
LayerNorm
Dropout
Mask
```

特别是：

- `history_eeg_310 -> EEG MLP` 前后可以使用 `LayerNorm`。
- `history_step_emb` 进入 pooling/attention/GRU/Transformer 前可以使用 `LayerNorm`。
- 所有历史聚合必须使用 `history_length` 生成 mask。

## 6. 第一版推荐配置

第一版 v1 归一化建议固定为：

```text
user_id                  embedding，不归一化
item_id                  embedding，不归一化
history_item_id          embedding，不归一化
c_video_type_c           embedding，不归一化
u_gender_c               embedding，不归一化

u_age_f                  train z-score
u_usage_f                train z-score

i_count_f                log1p + train z-score
i_laplace_var_f          log1p + train z-score
其他 i_* 连续特征        train z-score

history_eeg_310          train 有效历史 step 按维度 z-score
history emotion 四项     固定 (x - 1) / 4 缩放到 [0, 1]
```

## 7. 验证检查

完成归一化统计和接入后，建议检查：

1. train 中 `u_age_f`、`u_usage_f` 归一化后均值接近 0，标准差接近 1。
2. train 中 item 连续特征归一化后均值接近 0，标准差接近 1。
3. `i_count_f`、`i_laplace_var_f` 已先 `log1p` 再 z-score。
4. `history_eeg_310` 的 310 个维度在有效历史位置上均值接近 0，标准差接近 1。
5. 历史情绪评分缩放后主要落在 `[0, 1]`。
6. padding 位置不会参与统计、pooling 或 attention。
7. dev/test 使用的是 train 统计量，而不是各自重新统计。

## 8. 一句话总结

这版归一化方案的核心是：**ID 和类别特征走 embedding；用户年龄和使用强度、物品连续元特征、历史 EEG 做基于 train split 的标准化；长尾大尺度物品特征先 log1p 再标准化；历史情绪评分按固定评分范围缩放；所有历史 padding 都必须 mask 掉。**

### 9.2 修改 StrictPreCTRReader

修改文件：

```text
/root/autodl-tmp/src/helpers/StrictPreCTRReader.py
```

新增逻辑：

1. Reader 初始化时自动查找：

```text
{path}/{dataset}/normalization_stats.json
```

2. 如果文件存在，则加载统计量并执行归一化。
3. 如果文件不存在，则记录日志并保留原始连续特征值。

具体归一化位置：

- `user_meta.csv` 读入后，对 `u_age_f`、`u_usage_f` 做 z-score。
- `item_meta.csv` 读入后，对连续 `i_*` 做 z-score 或 `log1p + z-score`。
- `train/dev/test.csv` 读入并解析历史字段后，对 `history_eeg_310` 做逐维 z-score。
- 对 `history_interest`、`history_immersion`、`history_valence`、`history_arousal` 做固定 `(x - 1) / 4` 缩放。

没有归一化的字段：

```text
user_id
item_id
history_item_id
c_video_type_c
u_gender_c
history_label
history_length
label
time
```

其中 `history_label` 是历史反馈标签，不作为连续强度特征处理；如果后续模型使用它，应按二值/类别序列处理。

这样做的原因是：

- Reader 侧归一化可以让所有后续 v1 模型拿到一致尺度的连续输入。
- 原始 CSV 不被覆盖，便于审计和重新统计。
- 归一化逻辑跟数据读取绑定，不需要每个模型重复实现。
- 当统计文件缺失时保持兼容，不会破坏旧的读取流程。
