# /root/autodl-tmp 项目总览梳理

本文档用于记录当前 `/root/autodl-tmp` 项目的总体结构、运行链路，以及核心模型 `src/models/general/CTRLightGCN.py` 的主要逻辑，便于后续快速回顾。

## 1. 项目整体定位

该项目基于 ReChorus 2.0 推荐系统框架改造而来，整体目标是完成推荐任务，当前重点集中在 EEG 场景下的 CTR 预测。

ReChorus 的核心思想是把推荐实验拆成三类模块：

- Reader：负责读取数据、统计数据集信息、补充上下文特征。
- Model：负责定义模型结构、前向传播、损失函数和 batch 数据格式。
- Runner：负责训练循环、验证测试、早停、指标评估和预测结果保存。

当前项目在原始 ReChorus 框架上增加或改造了 EEG 相关模型，尤其是 `CTRLightGCN.py`，将 LightGCN、EEG 图神经网络编码和上下文特征融合结合起来做 CTR 预测。

## 2. 顶层目录结构

项目根目录 `/root/autodl-tmp` 下主要内容如下：

- `src/`：核心源码目录。
- `src/main.py`：训练、验证、测试的统一入口。
- `src/exp.py`：批量实验脚本，可重复执行命令并汇总结果。
- `src/models/`：模型定义目录，包含通用推荐、上下文推荐、序列推荐、重排模型等。
- `src/helpers/`：Reader 和 Runner 定义目录，负责数据读取、训练和评估流程。
- `src/utils/`：通用工具函数和网络层。
- `src/data/`：数据目录，当前重点数据集为 `EEGsvRec_eeg`。
- `docs/`：项目文档、教程和示例脚本。
- `log/`：训练日志和预测结果保存目录。
- `requirements.txt`：环境依赖。
- `quick_k_test.py`、`diagnose_k_issue.py`、`hyperparameter_analysis.py`、`k_experiment_config.py`：围绕 EEG DGCNN 中 k 值的调试和实验脚本。

## 3. `src/` 核心模块职责

### 3.1 `main.py`

`main.py` 是项目主入口，主要职责是：

1. 解析命令行参数。
2. 根据 `--model_name` 和 `--model_mode` 动态选择模型类。
3. 根据模型类中声明的 `reader` 和 `runner` 动态选择 Reader 和 Runner。
4. 加载或生成数据缓存 pickle。
5. 实例化模型、数据集和 Runner。
6. 训练模型并在 dev/test 上评估。
7. 保存最终预测结果。

对于当前重点模型，典型参数组合是：

```bash
python main.py \
  --model_name CTRLightGCN \
  --model_mode CTR \
  --dataset EEGsvRec_eeg \
  --path ./data/ \
  --include_user_features 1 \
  --include_item_features 1 \
  --include_situation_features 1 \
  --lr 0.001 \
  --l2 1e-08 \
  --emb_size 64 \
  --n_layers 3 \
  --batch_size 256 \
  --loss_n BCE
```

此时动态绑定关系为：

- 模型类：`CTRLightGCN.CTRLightGCNCTR`
- Reader：`ContextReader.ContextReader`
- Runner：`CTRRunner.CTRRunner`

### 3.2 `helpers/`

`helpers/` 目录负责数据读取和训练评估流程。

- `BaseReader.py`：读取 `train.csv`、`dev.csv`、`test.csv`，统计用户数、物品数、交互数，并构建用户点击集合。
- `ContextReader.py`：在 `BaseReader` 基础上读取上下文特征，包括用户特征、物品特征和情境特征。
- `BaseRunner.py`：通用训练循环，负责 epoch 训练、优化器、早停、模型保存和 Top-K 评估。
- `CTRRunner.py`：CTR 任务专用 Runner，使用 AUC、ACC、F1、LOG_LOSS 等指标。
- 其他 Reader/Runner：用于序列推荐、知识图谱、Impression 重排等任务。

### 3.3 `models/`

`models/` 是模型体系核心。

- `BaseModel.py`：定义基础模型、`GeneralModel`、`CTRModel` 以及内嵌 Dataset。
- `BaseContextModel.py`：定义上下文模型逻辑，负责把 `u_*`、`i_*`、`c_*` 特征补充进 `feed_dict`。
- `BaseImpressionModel.py`、`BaseRerankerModel.py`：用于 Impression 和重排任务。
- `models/general/`：通用推荐模型，例如 `LightGCN.py`、`BPRMF.py`、`NeuMF.py`、`CTRLightGCN.py`。
- `models/context/`：上下文感知 CTR/Top-K 模型，例如 DeepFM、DCN、WideDeep、AutoInt。
- `models/sequential/`：序列推荐模型，例如 SASRec、GRU4Rec、NARM。
- `models/context_seq/`：序列 + 上下文模型。
- `models/reranker/`：重排模型。

### 3.4 `utils/`

- `utils.py`：随机种子、日志格式化、DataFrame 列处理、batch 移动到设备等工具。
- `layers.py`：通用神经网络层。

### 3.5 `data/EEGsvRec_eeg/`

当前核心数据集为 `src/data/EEGsvRec_eeg/`。

主要文件：

- `train.csv`、`dev.csv`、`test.csv`：CTR 样本数据。
- `item_meta.csv`：物品元特征，字段以 `i_` 开头。
- `user_meta.csv`：用户元特征，字段以 `u_` 开头。
- 若干数据预处理脚本。

`train.csv` 等文件中的主要列包括：

- 基础列：`user_id`、`item_id`、`time`、`label`
- 情境列：`c_*`
- EEG 列：`c_EEG_data_310_f`

其中 `c_EEG_data_310_f` 是 310 维 EEG 特征，在模型中被 reshape 为 `[batch, 62, 5]`，即 62 个 EEG 电极节点，每个节点 5 维特征。

## 4. 数据流与训练流程

整体数据流如下：

1. `main.py` 解析参数。
2. 通过 `model_name.reader` 选择 Reader。
3. `ContextReader` 读取 CSV 数据，并根据参数决定是否加载：
   - item features
   - user features
   - situation features
4. Reader 生成 `corpus` 对象，并可缓存为 `.pkl` 文件。
5. `main.py` 实例化模型。
6. `main.py` 为 train/dev/test 分别构建 `Dataset`。
7. `Dataset._get_feed_dict()` 生成单条样本字典。
8. `collate_batch()` 将多条样本合并成 batch。
9. `Runner.fit()` 将 batch 送入模型。
10. 模型 forward 输出预测值和 label。
11. `CTRModel.loss()` 使用 BCE 或 MSE 计算损失。
12. Runner 反向传播、更新参数。
13. 每轮在 dev 上评估，并根据主指标早停。
14. 训练结束后加载最佳模型，在 dev/test 上评估并保存预测结果。

## 5. 上下文特征如何进入模型

上下文特征由 `ContextReader` 和 `BaseContextModel.py` 配合完成。

`ContextReader` 负责识别特征名：

- `u_*`：用户特征，来自 `user_meta.csv`
- `i_*`：物品特征，来自 `item_meta.csv`
- `c_*`：情境特征，来自 `train/dev/test.csv`

随后 `ContextCTRModel.Dataset._get_feed_dict()` 会调用 `get_context_feature()`，把这些特征加入单条样本的 `feed_dict`。

最终模型前向传播拿到的 batch 中不仅有：

- `user_id`
- `item_id`
- `label`

还会有：

- 用户特征，例如 `u_gender_c`、`u_age_f`
- 物品特征，例如 `i_music_tempo_f`、`i_brightness_f`
- 情境特征，例如 `c_view_duration_f`、`c_interest_f`、`c_EEG_data_310_f`

## 6. `CTRLightGCN.py` 文件总体结构

`src/models/general/CTRLightGCN.py` 是当前项目最关键的模型文件。

该文件主要包含以下模块：

- `DynamicalGraphConv`：DGCNN 的动态图卷积层。
- `EEGDGCNNEncoder`：基于 DGCNN 的 EEG 编码器。
- `EEGGCNEncoder`：基于固定图结构的 EEG GCN 编码器。
- `build_fully_connected_edge_index()`：构建 EEG 全连接图。
- `build_eeg_topology_edge_index()`：构建基于 EEG 电极拓扑的固定图。
- `LightGCNBase`：LightGCN 和上下文融合的核心基类。
- `LightGCN`：普通 Top-K 版本。
- `CTRLightGCNCTR`：当前重点 CTR 模型。
- `LightGCNImpression`：Impression 版本。
- `LGCNEncoder`：用户-物品二部图 LightGCN 编码器。

## 7. `CTRLightGCNCTR` 的继承关系

当前核心模型类是：

```python
class CTRLightGCNCTR(ContextCTRModel, LightGCNBase)
```

它同时继承：

- `ContextCTRModel`：CTR 任务 + 上下文特征 Dataset。
- `LightGCNBase`：LightGCN 编码、EEG 编码、上下文融合和预测逻辑。

类属性：

```python
reader = 'ContextReader'
runner = 'CTRRunner'
extra_log_args = ['emb_size', 'n_layers', 'batch_size']
```

因此模型自动使用：

- `ContextReader` 读取上下文特征。
- `CTRRunner` 做 CTR 训练和评估。

## 8. LightGCN 部分逻辑

LightGCN 用于学习用户和物品 ID 的协同过滤表示。

### 8.1 构建用户-物品二部图

`LightGCNBase.build_adjmat()` 根据训练集中 label 为正的用户-物品交互构建二部图邻接矩阵。

矩阵结构为：

```text
[ 0   R ]
[ R^T 0 ]
```

其中：

- `R` 是用户-物品交互矩阵。
- 用户和物品都被看作图节点。
- 边表示训练集中用户对物品的正反馈交互。

随后使用对称归一化：

```text
D^(-1/2) A D^(-1/2)
```

该归一化邻接矩阵用于 LightGCN 的 embedding 传播。

### 8.2 LGCNEncoder

`LGCNEncoder` 内部维护两个可训练参数：

- `user_emb`
- `item_emb`

前向传播时：

1. 拼接 user embedding 和 item embedding。
2. 使用稀疏邻接矩阵做多层传播。
3. 保存每一层 embedding。
4. 对第 0 层到第 n 层 embedding 求平均。
5. 再切分为 user embedding 和 item embedding。
6. 根据 batch 中的 `user_id` 和 `item_id` 取出对应向量。

当前常见配置为：

- `emb_size = 64`
- `n_layers = 3`

因此每个用户和物品最终表示都是 64 维。

## 9. EEG 编码逻辑

`CTRLightGCN.py` 中有两种 EEG 图编码方案。

### 9.1 固定图 GCN：`EEGGCNEncoder`

`EEGGCNEncoder` 使用 `torch_geometric.nn.GCNConv`。

输入：

```text
[batch, 62, 5]
```

含义：

- batch：样本数。
- 62：EEG 电极节点数。
- 5：每个电极的特征维度。

固定图结构可以来自：

- 全连接图：`build_fully_connected_edge_index()`
- EEG 电极拓扑图：`build_eeg_topology_edge_index()`

不过当前模型前向传播中实际使用的是 DGCNN，而不是固定图 GCN。

### 9.2 动态图 DGCNN：`EEGDGCNNEncoder`

当前实际使用的是 `EEGDGCNNEncoder`。

输入 EEG 原始特征：

```python
eeg_raw = feed_dict['c_EEG_data_310_f']  # [batch, 310]
eeg_feat = eeg_raw.view(-1, 62, 5)       # [batch, 62, 5]
```

随后送入：

```python
eeg_emb = self.eeg_dgcnn_encoder(eeg_feat)  # [batch, 16]
```

DGCNN 的核心特点是动态图构建：

1. 每次前向传播时，根据当前 batch 的 EEG 节点特征重新计算节点间距离。
2. 对每个电极节点选取 k 个最相似邻居。
3. 用邻居特征差 `neighbor - self` 和自身特征拼接。
4. 经过 `1x1 Conv2d + BatchNorm + ReLU`。
5. 对 k 个邻居做 max pooling。
6. 堆叠两层动态图卷积。
7. 使用全局平均池化得到 16 维 EEG 表示。

当前代码中 `k=8` 是硬编码在模型初始化中的：

```python
self.eeg_dgcnn_encoder = EEGDGCNNEncoder(in_channels=5, hidden_channels=32, out_channels=16, k=8)
```

根目录文档提到过 `--dgcnn_k`，但当前主模型文件中尚未完整接入命令行参数。

## 10. 上下文特征编码逻辑

除 EEG 外，其他情境特征在 `LightGCNBase.forward()` 中被筛选和编码。

当前筛选条件大意是：

- 必须是 `c_` 开头的情境特征。
- 排除 EEG。
- 排除 session 相关特征。
- 排除 view 相关特征。
- 排除 `c_video_order_f`。

保留下来的每个一维情境特征会经过：

```python
self.context_encoder = nn.Linear(1, 16)
```

也就是每个标量上下文特征被投影为 16 维向量。

注意：当前 `user_meta.csv` 和 `item_meta.csv` 中的 `u_*`、`i_*` 特征虽然会进入 `feed_dict`，但在 `CTRLightGCN.py` 当前前向逻辑里，主要显式处理的是 `c_*` 情境特征、`user_id` 和 `item_id`。也就是说，用户和物品元特征是否实际参与当前模型融合，需要结合后续代码版本确认。

## 11. 多粒度注意力融合逻辑

早期版本中，模型曾使用简单的全连接层把以下特征直接拼接预测：

```text
user embedding + item embedding + EEG embedding + context embeddings
```

当前代码中，主要使用新的多粒度注意力融合模块。

### 11.1 Token 化

不同来源的特征先被投影到统一 token 维度：

- user embedding：64 维 -> 64 维 token
- item embedding：64 维 -> 64 维 token
- EEG embedding：16 维 -> 64 维 token
- context embedding：16 维 -> 64 维 token

对应模块：

```python
self.user_token_proj = nn.Linear(64, self.token_dim)
self.item_token_proj = nn.Linear(64, self.token_dim)
self.eeg_token_proj = nn.Linear(16, self.token_dim)
self.context_token_proj = nn.Linear(16, self.token_dim)
```

### 11.2 Token Gate

每个 token 先经过门控网络，得到一个 0 到 1 的权重：

```python
token_gates = self.token_gate(tokens)
tokens = tokens * token_gates
```

作用是让模型动态判断哪些特征 token 更重要。

### 11.3 Self-Attention

所有 token 之间再做多头自注意力：

```python
attn_output, _ = self.self_attn(tokens, tokens, tokens)
tokens = self.norm_tokens(tokens + attn_output)
```

作用是建模 user、item、EEG、情境特征之间的相互关系。

### 11.4 Global Token Cross-Attention

模型定义了一个可学习的全局查询 token：

```python
self.global_token = nn.Parameter(torch.randn(1, 1, self.token_dim))
```

前向时它作为 query，对所有特征 token 做 cross-attention：

```python
global_attn_output, _ = self.cross_attn(global_token, tokens, tokens)
global_token = self.norm_global(global_token + global_attn_output)
```

作用是从所有特征 token 中汇聚出一个全局样本表示。

### 11.5 FFN 与预测

全局 token 再经过 FFN 增强：

```python
ffn_output = self.ffn(global_token)
global_token = self.norm_ffn(global_token + ffn_output)
```

最终预测：

```python
fused_feat = global_token.squeeze(1)
prediction = self.predictor(fused_feat).squeeze(-1)
```

`CTRLightGCNCTR.forward()` 会对 prediction 做 sigmoid，得到点击概率。

## 12. CTR 训练与评估

CTR 任务的样本由 `CTRModel.Dataset._get_feed_dict()` 构造。

每条样本包含：

```python
{
    'user_id': user_id,
    'item_id': [item_id],
    'label': [label]
}
```

上下文模型会在此基础上继续添加 `u_*`、`i_*`、`c_*` 特征。

损失函数默认为 BCE：

```python
loss = BCELoss(prediction, label)
```

`CTRRunner` 使用 CTR 指标评估：

- AUC
- ACC
- F1_SCORE
- LOG_LOSS

如果没有显式指定指标，`CTRRunner` 会把原本 Top-K 默认的 `NDCG,HR` 替换为 CTR 指标。

## 14. 当前代码中的注意点

### 14.1 日志结构和当前代码可能不完全一致

历史日志中打印过旧版结构，例如 `eeg_encoder` 和 `fc`，但当前 `CTRLightGCN.py` 已经改成 DGCNN + 多粒度注意力融合。因此查看实验结果时要注意日志对应的是哪一次代码版本。

### 14.2 `combined` 变量当前基本是遗留逻辑

`LightGCNBase.forward()` 中仍然构造了：

```python
combined = torch.cat([...], dim=-1)
```

但最终预测实际走的是 token attention 分支，而不是旧版 `self.fc(combined)`。

### 14.3 `EEGGCNEncoder` 保留但当前未实际使用

模型初始化中仍创建了固定图 GCN 编码器：

```python
self.eeg_gcn_encoder = EEGGCNEncoder(...)
```

但前向传播中实际使用的是：

```python
self.eeg_dgcnn_encoder(eeg_feat)
```

固定图 GCN 目前更像是对照实验或历史实现保留。

### 14.4 DGCNN 的 k 值暂未完整参数化

虽然根目录 `README_k_analysis.md` 提到 `--dgcnn_k`，但当前主模型中 k 值仍固定为 8。若后续要系统做 k 值实验，建议把 `dgcnn_k` 加入 `parse_model_args()` 并在 `CTRLightGCNCTR.__init__()` 中使用。

### 14.5 用户/物品元特征是否参与融合需继续确认

`ContextReader` 会读取 `user_meta.csv` 和 `item_meta.csv`，并把相关特征加入 `feed_dict`。但当前 `CTRLightGCN.py` 的显式融合逻辑主要遍历 `c_*` 情境特征，而不是 `u_*`、`i_*`。如果实验设计要求使用用户/物品元特征，需要检查或补充对应融合逻辑。

## 16. 一句话总结

当前项目可以理解为：在 ReChorus 的 Reader-Model-Runner 框架下，用 `ContextReader` 读取 EEG 情境数据和推荐交互数据，用 LightGCN 学习用户-物品协同过滤表示，用 DGCNN 动态编码 62 电极 EEG 特征，再通过多粒度注意力融合 user、item、EEG 和情境 token，最终用 BCE 训练 CTR 点击概率预测模型。
