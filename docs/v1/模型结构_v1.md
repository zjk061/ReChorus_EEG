# v1 模型结构设计

> 更新说明：当前 `EEGsvRec_eeg_strict_prectr` 数据生产逻辑已经变化，新增了 `history_label`、用户内时间 7:1:2 切分，以及 Reader 侧 train-only 归一化。本文前面章节保留为早期设计记录；后续实现请以文末“## 21. 当前最新 v1 模型结构设计”为准。

本文档记录当前暂定的 v1 模型结构设计。该结构用于适配新的严格前置 CTR 数据集：

```text
/root/autodl-tmp/src/data/EEGsvRec_eeg_strict_prectr/
```

v1 的核心目标是：

> 不再使用当前样本观看后才能获得的 EEG、问卷评分、播放比例、观看时长等后验特征，而是使用当前候选 item、用户/物品元特征，以及当前样本之前的历史交互序列来预测 CTR。

## 1. v1 模型核心思想

v1 模型采用“两层历史建模 + 非历史特征融合”的结构。

历史交互序列建模分两层：

1. 第一层：将每条样本的历史交互序列送入 Transformer Encoder，做历史序列内部的 self-attention。
2. 第二层：使用当前候选 item 的综合表示作为 query，对第一层输出的历史序列表示做 cross-attention。

第二层输出得到：

```text
candidate_aware_history
```

也就是“当前候选 item 感知的用户历史状态表示”。

该表示作为一路重要特征，与非历史特征一起送入最终融合结构，预测 pCTR。

整体概括为：

```text
历史序列 Transformer Encoder
-> 候选 item 对历史序列 Cross-Attention
-> 候选 item 感知历史表示
-> 与用户/物品/上下文特征融合
-> pCTR
```

## 2. v1 模型输入

v1 模型使用严格前置 CTR 派生数据集中的字段。

### 2.1 当前样本输入字段

允许输入：

```text
user_id
item_id
c_video_type_c
u_gender_c
u_age_f
u_usage_f
all i_* item features
history_item_id
history_eeg_310
history_interest
history_immersion
history_valence
history_arousal
history_length
```

其中：

- `user_id`：当前用户 ID。
- `item_id`：当前候选 item ID。
- `c_video_type_c`：当前候选 item 的视频类型，前提是推荐前可知。
- `u_*`：用户元特征。
- `i_*`：物品元特征。
- `history_*`：当前样本之前的历史交互序列。

### 2.2 当前样本标签

```text
label
```

### 2.3 禁止输入字段

v1 模型不使用当前样本后验字段：

```text
当前 c_EEG_data_310_f
当前 c_interest_f
当前 c_immersion_f
当前 c_valence_f
当前 c_arousal_f
当前 c_playrate_f
当前 c_view_duration_f
当前 end_time
```

这些字段只能作为后续样本的历史信息出现，不能作为当前样本输入。

## 3. v1 整体结构

v1 模型由以下主要模块组成：

```text
Candidate Item Encoder
User Meta Encoder
History Step Encoder
History Transformer Encoder
Candidate-to-History Cross-Attention
Fusion MLP
CTR Predictor
```

整体结构示意：

```text
Input
 ├── item_id, item_meta, c_video_type_c
 │     └── Candidate Item Encoder
 │             └── candidate_item_repr
 │
 ├── user_meta
 │     └── User Meta Encoder
 │             └── user_meta_repr
 │
 └── history_item_id, history_eeg_310, history_emotion, history_length
       └── History Step Encoder
       └── Transformer Encoder Self-Attention
       └── Candidate-to-History Cross-Attention
               └── candidate_aware_history

candidate_item_repr
+ user_meta_repr
+ candidate_aware_history
(+ optional user_id_emb)
 -> Fusion MLP
 -> sigmoid
 -> pCTR
```

## 4. Candidate Item Encoder

Candidate Item Encoder 用于构造当前候选 item 的综合表示。

候选 item 表示由三部分组成：

```text
item_id embedding
item_meta embedding
video_type embedding
```

### 4.1 item_id embedding

输入：

```text
item_id
```

处理：

```text
item_id -> Embedding -> item_id_emb
```

第一版 v1 中，建议先使用普通 embedding，而不是直接使用 LightGCN。

原因：

- 新数据方案更强调历史状态建模。
- 如果数据按用户划分，LightGCN 的用户侧泛化较弱。
- 普通 embedding 更简单，便于先验证 v1 主体结构。

### 4.2 item_meta embedding

物品元特征包括：

```text
i_music_tempo_f
i_count_f
i_height_c
i_width_c
i_brightness_f
i_dif_brightness_f
i_E_2D_f
i_dif_E_2D_f
i_contrast_f
i_laplace_var_f
i_color_cast_f
i_hue_f
i_dif_hue_f
i_saturation_f
i_dif_saturation_f
i_value_f
i_dif_value_f
```

处理建议：

```text
all i_* features
-> normalization
-> item_meta_mlp
-> item_meta_emb
```

需要注意，`i_count_f`、`i_laplace_var_f` 等字段数值尺度较大，后续实现时应考虑归一化或使用 normalization 层。

### 4.3 video_type embedding

输入：

```text
c_video_type_c
```

处理：

```text
c_video_type_c -> Embedding -> video_type_emb
```

如果第一版实现想更简单，也可以暂时使用：

```text
Linear(1, dim)
```

但从语义上看，`c_video_type_c` 更适合用类别 embedding。

### 4.4 candidate_item_repr

三部分特征融合：

```text
concat(item_id_emb, item_meta_emb, video_type_emb)
-> candidate_item_mlp
-> candidate_item_repr
```

输出：

```text
candidate_item_repr: [batch_size, d_model]
```

该表示后续有两个作用：

1. 作为最终融合特征之一。
2. 作为 cross-attention 的 query，去历史序列中选择与当前候选 item 最相关的历史记录。

## 5. User Meta Encoder

User Meta Encoder 用于构造当前用户的静态属性表示。

用户元特征：

```text
u_gender_c
u_age_f
u_usage_f
```

建议处理方式：

```text
u_gender_c -> embedding
u_usage_f -> embedding
u_age_f -> normalize/linear
concat -> user_meta_mlp -> user_meta_repr
```

输出：

```text
user_meta_repr: [batch_size, d_model]
```

### 5.1 是否使用 user_id embedding

v1 中可以保留一个可选的：

```text
user_id_emb
```

但不建议过度依赖它。

原因：

- 如果 train/dev/test 按用户划分，则 dev/test 用户没有参与训练。
- dev/test 用户 ID embedding 泛化能力弱。
- 新模型应更多依赖用户元特征和历史序列。

因此，`user_id_emb` 在 v1 中应作为可选辅助特征，而不是核心特征。

## 6. History Step Encoder

History Step Encoder 用于将每条历史交互记录编码为统一维度的 step embedding。

每条历史记录包含：

```text
history_item_id[t]
history_eeg_310[t]
history_interest[t]
history_immersion[t]
history_valence[t]
history_arousal[t]
```

目标输出：

```text
history_step_emb: [batch_size, max_history_len, d_model]
```

## 7. 历史 item 编码

输入：

```text
history_item_id: [batch_size, max_history_len]
```

处理：

```text
history_item_id -> item embedding -> hist_item_emb
```

输出：

```text
hist_item_emb: [batch_size, max_history_len, item_dim]
```

历史 item embedding 可以与当前 item 的 embedding 表共享权重。

## 8. 历史 EEG 编码

输入：

```text
history_eeg_310: [batch_size, max_history_len, 310]
```

v1 第一版建议使用 MLP 编码：

```text
history_eeg_310
-> eeg_mlp
-> hist_eeg_emb
```

输出：

```text
hist_eeg_emb: [batch_size, max_history_len, eeg_dim]
```

### 8.1 为什么第一版不用 DGCNN

初始版模型中当前样本 EEG 使用 DGCNN 编码。但 v1 第一版不建议直接对每个历史 step 使用 DGCNN。

原因：

- 历史 EEG 是三维序列：`[batch, history_len, 310]`。
- 如果每个历史 step 都 reshape 为 `[62, 5]` 后跑 DGCNN，计算量会乘以 `history_len`。
- 当前派生数据集本身已经较大，训练成本需要控制。
- 第一版更重要的是验证历史序列建模结构是否有效。

因此，v1 第一版采用：

```text
history_eeg_310 -> MLP
```

后续可以将 EEG MLP 替换为 DGCNN，作为对照实验。

## 9. 历史情绪评分编码

历史情绪评分包括：

```text
history_interest
history_immersion
history_valence
history_arousal
```

每个历史 step 拼成四维向量：

```text
history_emotion[t] = [
    interest,
    immersion,
    valence,
    arousal
]
```

整体形状：

```text
history_emotion: [batch_size, max_history_len, 4]
```

处理：

```text
history_emotion -> emotion_mlp -> hist_emotion_emb
```

输出：

```text
hist_emotion_emb: [batch_size, max_history_len, emotion_dim]
```

## 10. history_step_emb 构造

每条历史记录最终表示由三部分组成：

```text
hist_item_emb
hist_eeg_emb
hist_emotion_emb
```

建议使用 concat + MLP：

```text
concat(hist_item_emb, hist_eeg_emb, hist_emotion_emb)
-> history_step_mlp
-> history_step_emb
```

输出：

```text
history_step_emb: [batch_size, max_history_len, d_model]
```

使用 concat + MLP 的原因：

- 三种模态语义不同。
- MLP 比简单相加更灵活。
- 方便后续做消融实验。

## 11. 历史序列 mask

历史序列是变长的，batch padding 后需要 mask。

输入：

```text
history_length: [batch_size]
```

构造：

```text
history_mask: [batch_size, max_history_len]
```

含义：

- 有效历史位置：`False` 或 0。
- padding 位置：`True` 或 1。

该 mask 必须用于：

- Transformer Encoder 的 self-attention。
- Candidate-to-History Cross-Attention。
- 任何 pooling 操作。

否则 padding 的 0 会污染历史序列表示。

## 12. History Transformer Encoder

第一层历史建模结构是 Transformer Encoder。

输入：

```text
history_step_emb: [batch_size, max_history_len, d_model]
```

加入位置编码：

```text
history_step_emb + position_embedding
```

然后送入：

```text
TransformerEncoder
```

推荐第一版配置：

```text
d_model = 64
num_layers = 1
num_heads = 4
dropout = 0.2
```

输出：

```text
history_context_seq: [batch_size, max_history_len, d_model]
```

作用：

- 建模历史记录之间的相互关系。
- 让每个历史 step 表示吸收上下文。
- 捕捉历史 EEG 和历史情绪状态的动态变化。

### 12.1 为什么 Transformer 要小

当前数据量较小，复杂模型容易过拟合。因此 v1 第一版 Transformer Encoder 不宜太大。

建议：

```text
num_layers = 1 或 2
num_heads = 2 或 4
d_model = 64
dropout = 0.1 ~ 0.3
```

## 13. Candidate-to-History Cross-Attention

第二层历史建模结构是候选 item 到历史序列的 cross-attention。

### 13.1 Query

使用当前候选 item 的综合表示：

```text
candidate_item_repr
```

而不是单纯使用 `item_id_emb`。

原因：

- `candidate_item_repr` 同时包含 item ID、item meta、video type。
- 能更完整表达当前候选 item 的属性。
- 用它作为 query 更利于选择相关历史。

构造：

```text
query = candidate_item_repr.unsqueeze(1)
```

形状：

```text
[batch_size, 1, d_model]
```

### 13.2 Key / Value

使用第一层 Transformer Encoder 输出：

```text
key = history_context_seq
value = history_context_seq
```

形状：

```text
[batch_size, max_history_len, d_model]
```

### 13.3 Cross-Attention

执行：

```text
candidate_aware_history, attn_weights =
    cross_attention(
        query=candidate_item_repr,
        key=history_context_seq,
        value=history_context_seq,
        key_padding_mask=history_mask
    )
```

输出：

```text
candidate_aware_history: [batch_size, d_model]
```

含义：

> 当前候选 item 最关注的用户历史状态表示。

这是 v1 模型中最关键的一路历史特征。

### 13.4 Cross-Attention 的作用

它可以建模：

- 当前候选 item 与历史 item 的相关性。
- 当前候选 item 与历史 EEG 状态的相关性。
- 当前候选 item 与历史情绪评分状态的相关性。

相比简单 pooling，它能让不同候选 item 对同一个用户历史产生不同的历史表示。

## 14. 最终特征融合

最终参与预测的特征建议包括：

```text
candidate_item_repr
user_meta_repr
candidate_aware_history
optional user_id_emb
```

第一版建议使用 concat + MLP：

```text
fusion_input = concat(
    candidate_item_repr,
    user_meta_repr,
    candidate_aware_history,
    optional user_id_emb
)

fusion_hidden = fusion_mlp(fusion_input)
logit = predictor(fusion_hidden)
pCTR = sigmoid(logit)
```

输出：

```text
pCTR: [batch_size]
```

### 14.1 为什么第一版不用复杂 token attention 融合

当前初始版模型中有 token gate、self-attention、global token cross-attention 融合结构。

但 v1 第一版已经包含：

- 历史 Transformer Encoder。
- 候选 item 到历史序列的 Cross-Attention。

如果最终融合再使用复杂 token attention，模型可能过重。

因此，第一版建议最终融合使用更稳的：

```text
concat + MLP
```

后续如果模型稳定，再考虑把最终融合升级为 token attention。

## 15. v1 默认超参数建议

第一版推荐默认超参数：

```text
d_model = 64
history_eeg_dim = 32
history_emotion_dim = 16
item_meta_dim = 32
user_meta_dim = 16
max_history_len = 50
transformer_layers = 1
attention_heads = 4
dropout = 0.2
fusion_hidden = 64
```

如果过拟合明显，可以尝试：

```text
d_model = 32
max_history_len = 20
dropout = 0.3
减少或移除 user_id_emb
降低 transformer_layers
```

## 16. 是否使用 LightGCN

v1 第一版建议暂时不使用 LightGCN，或者只保留普通 item embedding。

原因：

- 新任务强调严格前置和历史状态建模。
- 如果数据按用户划分，dev/test 用户没有参与训练图，LightGCN 用户 embedding 泛化弱。
- 引入 LightGCN 会增加复杂度，不利于排查 v1 历史序列模块是否有效。

推荐路线：

```text
v1: 普通 embedding + meta + history attention
v1.1: 加回 LightGCN item/user 分支做对比
```

这样能更清楚判断历史序列模块本身是否有效。

## 17. v1 结构优点

该结构的优点包括：

- 符合严格前置 CTR，不使用当前后验特征。
- 能充分利用历史 EEG 和历史情绪评分。
- 第一层 self-attention 能建模历史内部关系。
- 第二层 cross-attention 能建模当前候选 item 与历史交互的匹配关系。
- 比纯 Transformer 更有推荐任务归纳偏置。
- 比单纯 DIN 更能建模历史内部上下文。
- 可以保留 cross-attention 权重，后续用于解释模型关注了哪些历史记录。

## 18. v1 结构风险和注意事项

### 18.1 过拟合风险

当前数据量较小，Transformer + Cross-Attention 有过拟合风险。

应控制：

```text
d_model
transformer_layers
attention_heads
max_history_len
```

并使用：

```text
dropout
weight decay
early stopping
```

### 18.2 历史 EEG 计算压力

`history_eeg_310` 维度高，历史序列又可能较长。第一版必须控制计算量。

建议：

```text
第一版使用 EEG MLP
后续再尝试 EEG DGCNN
```

### 18.3 必须正确处理 mask

所有历史序列相关模块都必须使用 `history_length` 构造 mask。

否则 padding 会污染：

- self-attention
- cross-attention
- mean pooling
- loss 之前的表示

### 18.4 item_meta 需要归一化

物品元特征尺度差异明显，后续实现时需要考虑归一化。

可选方式：

- 数据层预归一化。
- 模型内部 BatchNorm。
- 模型内部 LayerNorm。

### 18.5 不要过度依赖 user_id embedding

如果数据按用户划分，dev/test 用户 ID 在训练中不可见或学习不足。

因此：

```text
user_meta + history sequence
```

应作为用户表示的主要来源。

## 19. v1 前向传播流程总结

一次 forward 流程可以总结为：

```text
1. 读取当前候选 item 信息：
   item_id, item_meta, c_video_type_c

2. Candidate Item Encoder 得到：
   candidate_item_repr

3. 读取用户元特征：
   u_gender_c, u_age_f, u_usage_f

4. User Meta Encoder 得到：
   user_meta_repr

5. 读取历史序列：
   history_item_id
   history_eeg_310
   history_interest
   history_immersion
   history_valence
   history_arousal
   history_length

6. History Step Encoder 得到：
   history_step_emb

7. 根据 history_length 构造 history_mask

8. History Transformer Encoder 得到：
   history_context_seq

9. Candidate-to-History Cross-Attention 得到：
   candidate_aware_history

10. 拼接：
    candidate_item_repr
    user_meta_repr
    candidate_aware_history
    optional user_id_emb

11. Fusion MLP 输出 logit

12. sigmoid 得到 pCTR
```

## 20. 一句话总结

v1 模型暂定为：

> 一个轻量级的“历史序列 Transformer Encoder + 候选 item Cross-Attention + 非历史特征 MLP 融合”的严格前置 CTR 模型。

它既保留了方案 C 中历史序列 self-attention 的能力，又引入方案 D 中候选 item 感知历史选择的推荐归纳偏置，同时通过小模型规模、MLP EEG 编码、concat + MLP 融合来控制小数据集上的过拟合和计算风险。

## 21. 当前最新 v1 模型结构设计

本节基于当前最新数据生产逻辑重新规划 v1 模型结构。后续实现应以本节为准。

当前最新事实包括：

1. `EEGsvRec_eeg_strict_prectr` 是用户内时间切分数据集，而不是按用户划分。
2. 新版 `train/dev/test` 来自合并原始三份数据后，对每个用户按 `time` 排序并按约 `7:1:2` 重新切分。
3. `train/dev/test` 都覆盖同一批用户，任务语义是“用同一用户过去行为预测未来行为”。
4. 历史序列新增并计划使用 `history_label`。
5. 连续特征已通过 `normalization_stats.json` 在 `StrictPreCTRReader` 侧完成 train-only 归一化。
6. 当前样本仍不包含当前 EEG、当前问卷评分、播放比例、观看时长等后验字段。

### 21.1 最新任务定义

v1 模型要解决的问题是：

> 对同一用户，使用其当前时间之前的完整历史交互序列、用户元特征、当前候选 item 的 ID 和元特征，预测该用户未来当前样本是否产生正反馈。

形式上仍是 CTR 二分类：

```text
(user_id, item_id, time, user_meta, item_meta, history_sequence) -> label
```

但当前样本不使用任何观看当前 item 后才产生的后验信息。

### 21.2 最新输入字段

当前 v1 模型允许使用：

```text
user_id
item_id
c_video_type_c
u_gender_c
u_age_f
u_usage_f
all i_* item features
history_item_id
history_label
history_eeg_310
history_interest
history_immersion
history_valence
history_arousal
history_length
```

其中：

- `history_item_id`：历史 item 序列。
- `history_label`：历史交互正负反馈序列。
- `history_eeg_310`：历史 EEG 序列。
- `history_interest`、`history_immersion`、`history_valence`、`history_arousal`：历史四类情绪自评分序列。
- `history_length`：有效历史长度，用于 mask。

当前样本禁止使用：

```text
当前 c_EEG_data_310_f
当前 c_interest_f
当前 c_immersion_f
当前 c_valence_f
当前 c_arousal_f
当前 c_playrate_f
当前 c_view_duration_f
当前 end_time
c_session_mode_c
c_session_id_c
c_video_order_f
```

### 21.3 最新整体结构

最新 v1 仍采用“两层历史建模 + 非历史特征融合”结构：

```text
Candidate Item Encoder
User Encoder
History Step Encoder
History Transformer Encoder
Candidate-to-History Cross-Attention
Fusion MLP
CTR Predictor
```

整体流程：

```text
item_id + item_meta + c_video_type_c
  -> Candidate Item Encoder
  -> candidate_item_repr

user_id + user_meta
  -> User Encoder
  -> user_repr

history_item_id + history_label + history_eeg_310 + history emotion
  -> History Step Encoder
  -> history_step_emb
  -> History Transformer Encoder
  -> history_context_seq

candidate_item_repr as query
history_context_seq as key/value
  -> Candidate-to-History Cross-Attention
  -> candidate_aware_history

candidate_item_repr + user_repr + candidate_aware_history
  -> Fusion MLP
  -> sigmoid
  -> pCTR
```

### 21.4 Candidate Item Encoder

候选 item 表示由三部分组成：

```text
item_id_emb
item_meta_emb
video_type_emb
```

#### 21.4.1 item_id_emb

```text
item_id -> Embedding -> item_id_emb
```

当前由于是用户内时间切分，item 在 train 中出现较多，普通 item embedding 是合理的第一版选择。

#### 21.4.2 item_meta_emb

输入为全部 `i_*` 物品元特征。

注意：这些连续值已在 `StrictPreCTRReader` 中根据 `normalization_stats.json` 完成归一化：

- `i_count_f`、`i_laplace_var_f` 已做 `log1p + z-score`。
- 其他连续 `i_*` 已做 train z-score。

模型侧可以直接使用：

```text
normalized item_meta -> item_meta_mlp -> item_meta_emb
```

#### 21.4.3 video_type_emb

```text
c_video_type_c -> Embedding -> video_type_emb
```

`c_video_type_c` 是类别型推荐前可知特征，不做连续归一化。

#### 21.4.4 candidate_item_repr

```text
concat(item_id_emb, item_meta_emb, video_type_emb)
-> candidate_item_mlp
-> candidate_item_repr
```

输出：

```text
candidate_item_repr: [batch_size, d_model]
```

该表示既进入最终融合，也作为 cross-attention 的 query。

### 21.5 User Encoder

当前数据是用户内时间切分，因此可以合理使用：

```text
user_id embedding
```

用户表示由两部分组成：

```text
user_id_emb
user_meta_emb
```

#### 21.5.1 user_id_emb

```text
user_id -> Embedding -> user_id_emb
```

由于同一用户在 train/dev/test 中均出现，`user_id_emb` 不再是完全冷用户场景下的随机未训练表示。

但仍不建议只依赖 user_id，因为 v1 的目标是利用历史序列建模用户动态状态。

#### 21.5.2 user_meta_emb

用户元特征：

```text
u_gender_c
u_age_f
u_usage_f
```

处理建议：

```text
u_gender_c -> Embedding
u_age_f   -> 已归一化连续值
u_usage_f -> 已归一化连续值
concat -> user_meta_mlp -> user_meta_emb
```

其中 `u_age_f` 和 `u_usage_f` 已由 Reader 做 train z-score。

#### 21.5.3 user_repr

```text
concat(user_id_emb, user_meta_emb)
-> user_mlp
-> user_repr
```

输出：

```text
user_repr: [batch_size, d_model]
```

### 21.6 History Step Encoder

历史序列中每个 step 现在包含：

```text
history_item_id[t]
history_label[t]
history_eeg_310[t]
history_interest[t]
history_immersion[t]
history_valence[t]
history_arousal[t]
```

目标是为每个历史 step 构造统一维度表示：

```text
history_step_emb: [batch_size, max_history_len, d_model]
```

### 21.7 历史 item 编码

```text
history_item_id -> shared item embedding -> hist_item_emb
```

建议与当前候选 `item_id` 使用同一套 item embedding 表。

输出：

```text
hist_item_emb: [batch_size, max_history_len, item_dim]
```

### 21.8 历史 label 编码

`history_label` 是当前新增且计划使用的重要字段。

它表示每个历史 item 对应的正负反馈：

```text
0/1
```

推荐两种编码方式：

#### 21.8.1 Embedding 编码

```text
history_label -> Embedding(2, label_dim) -> hist_label_emb
```

优点：

- 明确把 label 当作离散反馈类型。
- 可以让模型学习正反馈和负反馈不同的语义向量。

#### 21.8.2 Scalar projection

```text
history_label.float().unsqueeze(-1)
-> Linear(1, label_dim)
-> hist_label_emb
```

优点：

- 实现简单。
- 适合只把 label 当作二值强度信号。

第一版更推荐使用：

```text
Embedding(2, label_dim)
```

原因是历史正负反馈是类别语义，不是连续强度。

输出：

```text
hist_label_emb: [batch_size, max_history_len, label_dim]
```

### 21.9 历史 EEG 编码

输入：

```text
history_eeg_310: [batch_size, max_history_len, 310]
```

当前 Reader 已经对其做 train 有效历史 step 的逐维 z-score。

v1 第一版仍建议使用 MLP：

```text
history_eeg_310
-> LayerNorm 或 Linear 前规范化层（可选）
-> eeg_mlp
-> hist_eeg_emb
```

输出：

```text
hist_eeg_emb: [batch_size, max_history_len, eeg_dim]
```

第一版不建议直接使用 DGCNN，因为每个历史 step 都跑 DGCNN 会显著增加计算量。

### 21.10 历史情绪编码

历史情绪包括：

```text
history_interest
history_immersion
history_valence
history_arousal
```

Reader 已经对它们做固定缩放：

```text
(x - 1) / 4
```

每个历史 step 拼成：

```text
history_emotion[t] = [
  history_interest[t],
  history_immersion[t],
  history_valence[t],
  history_arousal[t]
]
```

处理：

```text
history_emotion -> emotion_mlp -> hist_emotion_emb
```

输出：

```text
hist_emotion_emb: [batch_size, max_history_len, emotion_dim]
```

### 21.11 history_step_emb 构造

每个历史 step 的最终表示由四部分组成：

```text
hist_item_emb
hist_label_emb
hist_eeg_emb
hist_emotion_emb
```

推荐使用：

```text
concat(hist_item_emb, hist_label_emb, hist_eeg_emb, hist_emotion_emb)
-> history_step_mlp
-> history_step_emb
```

输出：

```text
history_step_emb: [batch_size, max_history_len, d_model]
```

`history_label` 的加入能让模型区分：

```text
用户历史中看过但负反馈的 item
用户历史中看过且正反馈的 item
```

这对推荐任务非常重要。

### 21.12 max_history_len 与 mask

虽然数据中保存完整历史，但训练时仍建议截断最近 `max_history_len` 条，例如：

```text
max_history_len = 50
```

候选值：

```text
20 / 50 / 100
```

根据 `history_length` 构造：

```text
history_mask: [batch_size, max_history_len]
```

所有 padding 位置都必须在以下模块中 mask 掉：

- History Transformer Encoder
- Candidate-to-History Cross-Attention
- 任何 pooling 或可解释性统计

### 21.13 History Transformer Encoder

第一层历史建模：

```text
history_step_emb + position_embedding
-> TransformerEncoder
-> history_context_seq
```

推荐第一版配置：

```text
d_model = 64
num_layers = 1
num_heads = 4
dropout = 0.2
```

输出：

```text
history_context_seq: [batch_size, max_history_len, d_model]
```

作用：

- 建模历史交互之间的依赖。
- 融合历史 item、label、EEG、情绪的上下文关系。
- 捕捉用户状态随时间变化的模式。

### 21.14 Candidate-to-History Cross-Attention

第二层历史建模：

```text
query = candidate_item_repr
key   = history_context_seq
value = history_context_seq
```

执行：

```text
candidate_aware_history, attn_weights =
    cross_attention(
        query=candidate_item_repr,
        key=history_context_seq,
        value=history_context_seq,
        key_padding_mask=history_mask
    )
```

输出：

```text
candidate_aware_history: [batch_size, d_model]
```

含义：

> 当前候选 item 视角下最相关的用户历史状态表示。

该模块负责建模当前候选 item 与用户历史 item、历史反馈、历史 EEG、历史情绪状态之间的匹配关系。

### 21.15 最终融合

最终融合特征建议包括：

```text
candidate_item_repr
user_repr
candidate_aware_history
```

第一版使用：

```text
concat(candidate_item_repr, user_repr, candidate_aware_history)
-> fusion_mlp
-> logit
-> sigmoid
-> pCTR
```

暂不建议第一版再加入复杂 token attention 融合。

原因：

- 历史侧已经有 Transformer 和 Cross-Attention。
- 数据量较小，最终融合过复杂容易过拟合。
- concat + MLP 更利于排查问题和做 baseline。

### 21.16 推荐默认超参数

第一版推荐：

```text
d_model = 64
item_id_dim = 32 或 64
history_label_dim = 8
history_eeg_dim = 32
history_emotion_dim = 16
item_meta_dim = 32
user_meta_dim = 16
max_history_len = 50
transformer_layers = 1
attention_heads = 4
dropout = 0.2
fusion_hidden = 64
```

如果过拟合明显：

```text
d_model 降到 32
max_history_len 降到 20
dropout 提到 0.3
transformer_layers 保持 1
减少 user_id_emb 维度
```

### 21.17 是否使用 LightGCN

在当前最新数据设定下，LightGCN 的问题比早期“按用户划分”设定小，因为同一用户会出现在 train/dev/test 中。

但 v1 第一版仍建议先不使用 LightGCN，原因是：

- 当前优先目标是验证历史序列建模。
- 普通 embedding + meta + history attention 更容易排查。
- LightGCN 会引入额外图构建和传播变量。
- 当前数据已经包含完整历史序列，用户状态主要应由历史序列学习。

推荐路线：

```text
v1: 普通 user/item embedding + meta + history Transformer/Cross-Attention
v1.1: 加回 LightGCN 分支做对照
```

### 21.18 当前最新 v1 结构总结

当前最新 v1 结构为：

```text
user_id, user_meta
  -> User Encoder
  -> user_repr

item_id, item_meta, c_video_type_c
  -> Candidate Item Encoder
  -> candidate_item_repr

history_item_id, history_label, history_eeg_310, history emotion
  -> History Step Encoder
  -> Transformer Encoder
  -> history_context_seq

candidate_item_repr + history_context_seq
  -> Cross-Attention
  -> candidate_aware_history

concat(user_repr, candidate_item_repr, candidate_aware_history)
  -> Fusion MLP
  -> pCTR
```

一句话概括：

> 当前最新 v1 模型是一个面向用户内时间预测的严格前置 CTR 模型。它使用当前候选 item 综合表示作为 query，对包含 `history_item_id`、`history_label`、历史 EEG 和历史情绪的用户历史序列做 Transformer + Cross-Attention 建模，再与用户表示和候选 item 表示融合预测 pCTR。
