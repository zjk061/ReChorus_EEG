### 0.2 对已有预测 CSV 做阈值扫描

已有 best 模型的预测文件，先分析完，解决「F1 很低 = 模型很差」的误解。

```bash
cd /root/autodl-tmp/src
conda activate eeg3104

python - <<'PY'
import pandas as pd
import numpy as np
from sklearn.metrics import roc_auc_score, f1_score

def analyze(path, phase):
    df = pd.read_csv(path)
    y, p = df["label"].values, df["pCTR"].values
    print(f"\n=== {phase} ===")
    print(f"n={len(df)}, pos_rate={y.mean():.3f}, pCTR mean={p.mean():.3f}")
    print(f"AUC={roc_auc_score(y, p):.4f}")
    print(f"F1@0.5={f1_score(y, (p>=0.5).astype(int)):.4f}")
    best_f1, best_t = 0, 0.5
    for t in np.linspace(0.05, 0.95, 19):
        f = f1_score(y, (p >= t).astype(int))
        if f > best_f1:
            best_f1, best_t = f, t
    print(f"best F1={best_f1:.4f} at threshold={best_t:.2f}")

base = "../log/EEG_DGCN_v1CTR/EEG_DGCN_v1CTR__EEGsvRec_eeg_strict_prectr__0__lr=0"
analyze(f"{base}/rec-EEG_DGCN_v1CTR-dev.csv", "dev")
analyze(f"{base}/rec-EEG_DGCN_v1CTR-test.csv", "test")
PY
```

**预期结论（与已有分析一致）：**

- AUC 尚可（dev ~0.73，test ~0.67）  
- F1@0.5 低，但 dev 上最优阈值约 0.15 时 F1 会明显升高  

**产出：** 一张小表，写入实验记录，作为后续所有 run 的对比基准。

## 阶段 1：代码准备（1 天，为 ablation 服务）

> 对应《v1训练日志问题分析.md》P1 问题 5、6。  
> 当前 `EEG_DGCN_v1.py` **没有** ablation 开关，需要先加。

### 1.1 在模型中增加 2 个 ablation 参数

在 `src/models/general/EEG_DGCN_v1.py` 的 `parse_model_args` 中增加：

```python
parser.add_argument('--use_history', type=int, default=1,
                    help='1: use history branch; 0: static baseline')
parser.add_argument('--use_history_eeg', type=int, default=1,
                    help='1: encode history EEG; 0: zero EEG embedding')
```

在 `__init__` 中保存：

```python
self.use_history = args.use_history
self.use_history_eeg = args.use_history_eeg
```

在 `_encode_history` 开头加：

```python
if not self.use_history:
    return torch.zeros(batch_size, self.emb_size, device=self.device)
```

在 EEG 编码处改为：

```python
if not self.use_history_eeg:
    history_eeg_emb = torch.zeros(
        batch_size, seq_len, self.history_eeg_dim, device=self.device)
else:
    history_eeg_emb = self.history_eeg_encoder(history_eeg)
```

**说明：**

- `use_history=0` 时 history 分支输出全零，fusion MLP 仍保留第三路输入  
- 这是最小改动 ablation；若结果差异很大，已足够判断 history 有无增益  
- 若差异很小，再考虑做「两路 fusion」的 static 版本  

### 1.2 复制训练脚本，形成实验脚本族

在 `src/scripts/` 下新建（基于 `run_strict_prectr_v1_train.sh`）：

| 脚本名 | 关键差异 | 实验 ID |
|--------|----------|---------|
| `run_ablation_A_full.sh` | 与当前 train 相同 + `--main_metric AUC` | A（baseline，可复现） |
| `run_ablation_B_no_history.sh` | `--use_history 0` | B |
| `run_ablation_C_no_eeg.sh` | `--use_history 1 --use_history_eeg 0` | C |
| `run_ablation_D_small_reg.sh` | `--emb_size 32 --fusion_hidden 32 --dropout 0.4 --l2 1e-4 --lr 5e-4` | D |

**每个脚本必须包含：**

```bash
--main_metric AUC \
--random_seed 0 \   # 固定种子，便于对比
```

**每个脚本不要改：** dataset、split、epoch 上限、early_stop、batch_size（先保持一致）。

## 阶段 2：Ablation 实验（1–2 天，按顺序跑）

> 对应 P1 问题 3、4、6。  
> **一次只跑一个脚本**，跑完填表再跑下一个。

### 2.1 实验执行顺序

```bash
cd /root/autodl-tmp/src
conda activate eeg3104

bash scripts/run_ablation_A_full.sh      # 复现 baseline
bash scripts/run_ablation_B_no_history.sh
bash scripts/run_ablation_C_no_eeg.sh
bash scripts/run_ablation_D_small_reg.sh
```

每次训练约 2 分钟；4 次合计 <30 分钟 GPU 时间。主要时间花在读日志、填表、写结论。

### 2.2 每次跑完立即提取这 5 项

从对应 log 文件末尾读取：

1. `Best Iter(dev)=` → best epoch  
2. `Dev After Training` → dev AUC / LOG_LOSS  
3. `Test After Training` → **test AUC**（最重要）  
4. 参数量 `#params:`（D 实验应明显更小）  
5. 是否早停、第几轮停  

### 2.3 结果解读决策树

```
B（无 history）test AUC ≈ A（full）
  → 历史模块几乎无增益，优先做 static 小模型，暂缓堆 Transformer

B 明显低于 A（差 ≥ 0.02）
  → 历史有用；再看 C

C（无 EEG）test AUC ≈ B 或 A
  → EEG 无增益，可保留 label+emotion 历史，简化 EEG 编码

C 明显低于 A
  → EEG 有增益，值得保留

D（小模型+强正则）test AUC ≥ A 且 best_epoch 更晚 / dev-test gap 更小
  → 过拟合主因是容量过大，v1.1 以 D 的配置为起点

D 仍明显低于 A
  → 不是单靠正则能解决，需简化架构或减少特征
```

**当前 baseline（实验 A 目标值）：**

| 指标 | Dev | Test |
|------|-----|------|
| AUC | 0.735 | 0.667 |
| LOG_LOSS | 0.638 | 0.728 |

以 **test AUC** 与 0.667 比较，差 0.01 以内可视为「同一水平」。

## 阶段 3：根据 ablation 结果选主路线（第 3–5 天）

只走**一条**主路线，不要同时改架构又改数据又改超参。

### 路线 1：history / EEG 有增益，但过拟合严重（A ≈ C/B 且 D 有改善）

**操作：**

1. 以实验 D 的参数为 v1.1 默认配置  
2. 再跑 2 个单变量微调（二选一或各跑一遍）：
   - `--dropout 0.5`（其余同 D）  
   - `--early_stop 5`（更早停）  
3. 报告 test AUC，不再追 train loss  

**成功标准：** test AUC ≥ 0.67，且 best epoch ≥ 5（说明没有第 1 轮就见顶）

### 路线 2：history 无增益（B ≈ A）

**操作：**

1. 暂停投入 Transformer / Cross-Attention  
2. 新建或改用 **static CTR 模型**（仅 user + candidate item + meta）  
3. 用相同数据、相同评估流程训练 static baseline  
4. 若 static test AUC ≥ full model，则 v2 以 static 为主，history 作为可选扩展  

**成功标准：** 用更少参数达到相近或更好 test AUC

### 路线 3：EEG 无增益但 history 有增益（B < A，C ≈ A）

**操作：**

1. 保留 history_label + emotion + item_id 序列  
2. 去掉 `history_eeg_encoder` 或固定 `--use_history_eeg 0`  
3. 减小 `history_eeg_dim` 相关计算，降低参数量

## 当前最不建议做的事

1. **不要** 同时改 batch_size、emb_size、history_max、lr  
2. **不要** 用 F1@0.5 或 train loss 选模型  
3. **不要** 在 ablation 未完成前上大改动（加层、加 GCN、改 split）  
4. **不要** 因 dev AUC 0.73 就认为 test 也会 0.73——**对外报告以 test 为准**  
5. **不要** 扩 epoch 到 200「让 loss 再降」——日志已证明 epoch 3 后只会过拟合
