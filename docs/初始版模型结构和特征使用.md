# 初始版 CTRLightGCN 模型结构和特征使用说明

本文档基于当前代码文件：

```text
/root/autodl-tmp/src/models/general/CTRLightGCN.py
```

梳理当前初始版模型的整体结构、各模块职责、前向传播流程、实际使用的特征，以及当前代码中保留但未实际使用的部分。

需要特别说明：本文档描述的是当前 `CTRLightGCN.py` 中已有模型结构，即仍使用当前样本 EEG 和当前样本部分情境特征的初始版模型；它不是后续严格前置 CTR 新数据方案下的模型结构。

## 1. 当前文件整体结构

`CTRLightGCN.py` 主要包含以下模块：

```text

EEGDGCNNEncoder
EEGGCNEncoder
build_fully_connected_edge_index
build_eeg_topology_edge_index
LightGCNBase
LightGCN
CTRLightGCNCTR
LightGCNImpression
LGCNEncoder
```

从功能上看，可以分为四类：

1. EEG 图编码模块：
   - `DynamicalGraphConv`
   - `EEGDGCNNEncoder`
   - `EEGGCNEncoder`
   - `build_fully_connected_edge_index`
   - `build_eeg_topology_edge_index`

2. LightGCN 推荐表示模块：
   - `LightGCNBase.build_adjmat`
   - `LGCNEncoder`

3. CTR 模型主体：
   - `LightGCNBase`
   - `CTRLightGCNCTR`

4. 其他任务版本：
   - `LightGCN`
   - `LightGCNImpression`

当前重点使用的是：

```python
class CTRLightGCNCTR(ContextCTRModel, LightGCNBase)
```

它对应 CTR 预测任务。

## 2. 当前核心模型类：CTRLightGCNCTR

当前 CTR 任务使用的模型类是：

```python
class CTRLightGCNCTR(ContextCTRModel, LightGCNBase):
    reader = 'ContextReader'
    runner = 'CTRRunner'
    extra_log_args = ['emb_size', 'n_layers', 'batch_size']
```

它同时继承：

- `ContextCTRModel`
- `LightGCNBase`

### 2.1 ContextCTRModel 的作用

`ContextCTRModel` 来自：

```text
/root/autodl-tmp/src/models/BaseContextModel.py
```

它的主要作用是：

1. 继承 CTR 任务的数据格式和 loss 逻辑。
2. 通过 Dataset 将上下文特征加入每条样本的 `feed_dict`。
3. 让模型可以使用 `ContextReader` 读取 `u_*`、`i_*`、`c_*` 特征。

CTR 样本基础格式来自 `CTRModel.Dataset._get_feed_dict()`：

```python
feed_dict = {
    'user_id': user_id,
    'item_id': [item_id],
    'label': [label]
}
```

随后 `ContextCTRModel.Dataset._get_feed_dict()` 调用：

```python
get_context_feature(feed_dict, index, self.corpus, self.data)
```

把用户、物品、情境上下文特征补充进 `feed_dict`。

### 2.2 LightGCNBase 的作用

`LightGCNBase` 是当前模型的大部分结构定义和前向传播主体。

它负责：

1. 构建用户-物品二部图。
2. 初始化 LightGCN 编码器。
3. 初始化上下文特征编码器。
4. 初始化 token attention 融合模块。
5. 在 forward 中组织 user、item、EEG、context 特征并输出预测值。

### 2.3 CTRLightGCNCTR 的初始化

`CTRLightGCNCTR.__init__()` 中执行：

```python
ContextCTRModel.__init__(self, args, corpus)
self._base_init(args, corpus)
self.loss_fn = nn.BCELoss()
```

然后初始化 EEG 编码器：

```python
self.eeg_num_nodes = 62
self.eeg_edge_index = build_fully_connected_edge_index(self.eeg_num_nodes)
self.eeg_gcn_encoder = EEGGCNEncoder(...)
self.eeg_dgcnn_encoder = EEGDGCNNEncoder(in_channels=5, hidden_channels=32, out_channels=16, k=8)
```

注意：虽然同时初始化了 `eeg_gcn_encoder` 和 `eeg_dgcnn_encoder`，但当前 forward 实际使用的是 `eeg_dgcnn_encoder`。

## 4. LightGCN 用户-物品协同过滤分支

LightGCN 分支负责根据 `user_id` 和 `item_id` 学习协同过滤表示。

### 4.1 用户-物品二部图构建

`LightGCNBase._base_init()` 中执行：

```python
self.norm_adj = self.build_adjmat(corpus.n_users, corpus.n_items, corpus.train_clicked_set)
```

这里的 `corpus.train_clicked_set` 来自 Reader，表示训练集中 `label == 1` 的正反馈交互集合。

因此，LightGCN 图只基于训练集中正样本构建。

`build_adjmat()` 先构建用户-物品交互矩阵 `R`：

```text
R[user, item] = 1
```

再构建二部图邻接矩阵：

```text
[ 0   R  ]
[ R^T 0  ]
```

然后做对称归一化：

```text
D^(-1/2) A D^(-1/2)
```

得到 `norm_adj`，用于 LightGCN 的稀疏矩阵传播。

### 4.2 LGCNEncoder

`LGCNEncoder` 维护两个可训练 embedding：

```python
user_emb: [user_count, emb_size]
item_emb: [item_count, emb_size]
```

当前默认：

```text
emb_size = 64
n_layers = 3
```

前向传播流程：

1. 拼接用户和物品 embedding：

```python
ego_embeddings = torch.cat([user_emb, item_emb], 0)
```

2. 用归一化邻接矩阵做多层传播：

```python
ego_embeddings = torch.sparse.mm(self.sparse_norm_adj, ego_embeddings)
```

3. 保存第 0 层到第 `n_layers` 层的 embedding。

4. 对所有层结果求平均：

```python
all_embeddings = torch.mean(all_embeddings, dim=1)
```

5. 切分回用户 embedding 和物品 embedding。

6. 根据当前 batch 的 `user_id` 和 `item_id` 取出对应向量：

```python
user_embeddings = user_all_embeddings[users, :]
item_embeddings = item_all_embeddings[items, :]
```

在当前 CTR 数据中，`item_id` 在 `feed_dict` 中形状通常是：

```text
[batch_size, 1]
```

所以 `i_embed` 初始形状通常是：

```text
[batch_size, 1, 64]
```

随后在 `LightGCNBase.forward()` 中执行：

```python
i_embed = i_embed.squeeze(dim=1)
```

变成：

```text
[batch_size, 64]
```

最终 LightGCN 分支输出：

```text
u_embed: [batch_size, 64]
i_embed: [batch_size, 64]
```

## 5. EEG 编码分支

当前文件中存在两套 EEG 图编码实现：

1. 动态图 DGCNN：`EEGDGCNNEncoder`
2. 固定图 GCN：`EEGGCNEncoder`

但当前前向传播实际使用的是 DGCNN。

## 6. DynamicalGraphConv

`DynamicalGraphConv` 是 DGCNN 的基础动态图卷积层。

初始化：

```python
class DynamicalGraphConv(nn.Module):
    def __init__(self, in_channels, out_channels, k=8):
        self.k = k
        self.conv = nn.Conv2d(in_channels * 2, out_channels, kernel_size=1, bias=False)
        self.bn = nn.BatchNorm2d(out_channels)
```

核心思想：

1. 每次 forward 根据当前节点特征重新计算节点间相似关系。
2. 对每个节点选择 `k` 个近邻。
3. 构造邻居差分特征。
4. 用 `1x1 Conv2d + BatchNorm + ReLU` 更新节点特征。
5. 对 k 个邻居做 max pooling。

### 6.1 knn_graph

输入：

```text
x: [batch, channels, num_nodes]
```

当前 EEG 第一层中为：

```text
[batch, 5, 62]
```

它会计算节点之间的欧几里得距离，然后选取 top-k 近邻：

```python
idx = pairwise_distance.topk(k=k, dim=-1)[1]
```

输出：

```text
idx: [batch, num_nodes, k]
```

### 6.2 get_graph_feature

`get_graph_feature()` 根据近邻索引构造动态图特征：

```python
feature = torch.cat((feature - x, x), dim=3)
```

也就是说，每个节点的边特征由两部分组成：

```text
邻居特征 - 当前节点特征
当前节点自身特征
```

拼接后形状为：

```text
[batch, 2 * channels, num_nodes, k]
```

### 6.3 forward

动态图卷积前向传播：

```python
x = self.get_graph_feature(x, self.k)
x = self.conv(x)
x = self.bn(x)
x = F.relu(x)
x = x.max(dim=-1)[0]
```

输出：

```text
[batch, out_channels, num_nodes]
```

## 7. EEGDGCNNEncoder

`EEGDGCNNEncoder` 是当前实际使用的 EEG 编码器。

初始化：

```python
self.dgcnn1 = DynamicalGraphConv(in_channels, hidden_channels, k)
self.dgcnn2 = DynamicalGraphConv(hidden_channels, out_channels, k)
self.global_pool = nn.AdaptiveAvgPool1d(1)
```

在 `CTRLightGCNCTR.__init__()` 中使用：

```python
EEGDGCNNEncoder(in_channels=5, hidden_channels=32, out_channels=16, k=8)
```

### 7.1 输入格式

当前样本 EEG 原始输入来自：

```python
feed_dict['c_EEG_data_310_f']
```

形状为：

```text
[batch_size, 310]
```

在 `LightGCNBase.forward()` 中 reshape：

```python
eeg_feat = eeg_raw.view(-1, 62, 5)
```

得到：

```text
[batch_size, 62, 5]
```

含义：

```text
62 个 EEG 电极节点
每个电极 5 维特征
总维度 62 * 5 = 310
```

### 7.2 编码流程

`EEGDGCNNEncoder.forward()` 中：

1. 输入：

```text
[batch, 62, 5]
```

2. 转置：

```python
x = x.transpose(2, 1)
```

变成：

```text
[batch, 5, 62]
```

3. 第一层动态图卷积：

```text
[batch, 5, 62] -> [batch, 32, 62]
```

4. 第二层动态图卷积：

```text
[batch, 32, 62] -> [batch, 16, 62]
```

5. 全局平均池化：

```text
[batch, 16, 62] -> [batch, 16, 1]
```

6. squeeze：

```text
[batch, 16]
```

最终 EEG 分支输出：

```text
eeg_emb: [batch_size, 16]
```

## 8. EEGGCNEncoder 和固定图结构

`EEGGCNEncoder` 是固定图 GCN 编码器。

它使用：

```python
torch_geometric.nn.GCNConv
```

结构为：

```python
self.gcn1 = GCNConv(in_channels, hidden_channels)
self.gcn2 = GCNConv(hidden_channels, out_channels)
```

输入同样是：

```text
[batch, 62, 5]
```

处理方式：

1. reshape 为：

```text
[batch * 62, 5]
```

2. 为每个 batch 样本复制一份 `edge_index`。

3. 经过两层 GCN。

4. 用 `global_mean_pool` 聚合成：

```text
[batch, out_channels]
```

### 8.1 固定图 edge_index

文件中有两种构图函数：

1. `build_fully_connected_edge_index(num_nodes)`
2. `build_eeg_topology_edge_index()`

当前 `CTRLightGCNCTR.__init__()` 中实际初始化的是：

```python
self.eeg_edge_index = build_fully_connected_edge_index(self.eeg_num_nodes)
self.eeg_gcn_encoder = EEGGCNEncoder(...)
```

也就是说，固定 GCN 分支当前使用的是全连接图。

但在 `LightGCNBase.forward()` 中，实际执行的是：

```python
eeg_emb = self.eeg_dgcnn_encoder(eeg_feat)
```

而不是：

```python
eeg_emb = self.eeg_gcn_encoder(eeg_feat)
```

因此，`EEGGCNEncoder` 当前属于保留代码或对照实验代码，不是当前主预测路径。

## 9. 普通情境特征编码分支

除 EEG 外，当前模型还会遍历 `feed_dict` 中的 `c_*` 字段，筛选部分情境特征。

筛选逻辑：

```python
for key in feed_dict:
    if key[:2]=='c_' \
       and key[2:5] != 'EEG' \
       and key[2:9] != 'session' \
       and key[2:6] != 'view' \
       and key != 'c_video_order_f':
        context2d = feed_dict[key].unsqueeze(1)
        context16 = self.context_encoder(context2d.float())
        self.context_emb.append(context16)
```

也就是说，模型只使用满足以下条件的 `c_*` 特征：

1. 必须以 `c_` 开头。
2. 排除 EEG：

```text
c_EEG_data_310_f
```

3. 排除 session 相关：

```text
c_session_mode_c
c_session_id_c
```

4. 排除 view 相关：

```text
c_view_duration_f
```

5. 排除：

```text
c_video_order_f
```

在当前原始数据字段下，实际会被保留下来的普通情境特征是：

```text
c_arousal_f
c_immersion_f
c_interest_f
c_playrate_f
c_valence_f
c_video_type_c
```

每个特征都是一维标量，先扩展为：

```text
[batch_size, 1]
```

再经过：

```python
self.context_encoder = nn.Linear(1, 16)
```

得到：

```text
[batch_size, 16]
```

所有普通情境特征编码后被存入：

```python
self.context_emb
```

## 12. 多粒度 token attention 融合模块

当前模型没有使用简单拼接后全连接层作为最终预测主路径，而是使用 token attention 融合。

虽然 forward 中仍然构造了：

```python
combined = torch.cat([u_embed, i_embed, eeg_emb], dim=-1)
for feature in self.context_emb:
    combined = torch.cat([combined, feature], dim=-1)
```

但随后旧的 FC 预测已经注释：

```python
# prediction = self.fc(combined).squeeze(-1)
```

当前真正使用的是 token attention 分支。

## 13. Token 化

不同来源的特征先被投影到统一 token 维度：

```python
self.token_dim = 64
self.user_token_proj = nn.Linear(64, self.token_dim)
self.item_token_proj = nn.Linear(64, self.token_dim)
self.eeg_token_proj = nn.Linear(16, self.token_dim)
self.context_token_proj = nn.Linear(16, self.token_dim)
```

对应关系：

| 输入特征 | 原始维度 | token 维度 |
| --- | ---: | ---: |
| user embedding | 64 | 64 |
| item embedding | 64 | 64 |
| EEG embedding | 16 | 64 |
| 每个普通 context embedding | 16 | 64 |

当前使用 6 个普通情境特征时，token 数量为：

```text
1 user token
1 item token
1 EEG token
6 context tokens
= 9 tokens
```

构造 token：

```python
token_list = [
    self.user_token_proj(u_embed),
    self.item_token_proj(i_embed),
    self.eeg_token_proj(eeg_emb)
]
for ctx_emb in self.context_emb:
    token_list.append(self.context_token_proj(ctx_emb))
tokens = torch.stack(token_list, dim=1)
```

最终：

```text
tokens: [batch_size, num_tokens, 64]
```

## 14. Token gate

每个 token 先经过门控网络：

```python
self.token_gate = nn.Sequential(
    nn.Linear(self.token_dim, self.token_dim),
    nn.GELU(),
    nn.Linear(self.token_dim, 1),
    nn.Sigmoid()
)
```

前向传播：

```python
token_gates = self.token_gate(tokens)
tokens = tokens * token_gates
```

其中：

```text
token_gates: [batch_size, num_tokens, 1]
```

作用是为每个特征 token 学习一个动态权重，使模型可以根据样本内容调整不同特征的重要性。

## 15. Self-Attention

门控后的 token 会进入多头自注意力：

```python
self.self_attn = nn.MultiheadAttention(
    embed_dim=self.token_dim,
    num_heads=4,
    batch_first=True,
    dropout=0.1
)
```

前向传播：

```python
attn_output, _ = self.self_attn(tokens, tokens, tokens)
tokens = self.norm_tokens(tokens + attn_output)
```

作用是建模不同特征 token 之间的相互关系，例如：

- 用户 embedding 与物品 embedding 的交互。
- EEG 状态与情绪评分的关系。
- 视频类型与用户当前状态的关系。
- 播放比例、兴趣、沉浸、情绪评分之间的关联。

## 16. Global token cross-attention

模型定义了一个可学习全局 token：

```python
self.global_token = nn.Parameter(torch.randn(1, 1, self.token_dim))
```

前向传播时扩展到 batch：

```python
global_token = self.global_token.expand(batch_size, -1, -1)
```

然后使用 cross-attention 从所有特征 token 中汇聚信息：

```python
global_attn_output, _ = self.cross_attn(global_token, tokens, tokens)
global_token = self.norm_global(global_token + global_attn_output)
```

作用是学习一个全局样本表示，相当于让全局查询 token 从 user、item、EEG、context tokens 中提取对预测最有用的信息。

## 17. FFN 和最终预测

全局 token 再经过 FFN：

```python
self.ffn = nn.Sequential(
    nn.Linear(self.token_dim, self.token_dim * 2),
    nn.GELU(),
    nn.Dropout(0.1),
    nn.Linear(self.token_dim * 2, self.token_dim)
)
```

前向传播：

```python
ffn_output = self.ffn(global_token)
global_token = self.norm_ffn(global_token + ffn_output)
```

然后进入最终预测层：

```python
self.predictor = nn.Sequential(
    nn.Linear(self.token_dim, self.token_dim // 2),
    nn.GELU(),
    nn.Dropout(0.1),
    nn.Linear(self.token_dim // 2, 1)
)
```

预测：

```python
fused_feat = global_token.squeeze(1)
prediction = self.predictor(fused_feat).squeeze(-1)
```

输出：

```text
prediction: [batch_size]
```

## 18. CTRLightGCNCTR.forward 输出

`LightGCNBase.forward()` 返回：

```python
{
    'prediction': prediction.view(feed_dict['batch_size'], -1),
    'u_v': u_v,
    'i_v': i_v
}
```

其中：

- `prediction` 是未 sigmoid 的预测 logit。
- `u_v` 和 `i_v` 是保留的用户/物品表示，当前 CTR loss 中不直接使用。

`CTRLightGCNCTR.forward()` 会进一步处理：

```python
out_dict = LightGCNBase.forward(self, feed_dict)
out_dict['prediction'] = out_dict['prediction'].view(-1).sigmoid()
out_dict['label'] = feed_dict['label'].view(-1)
return out_dict
```

因此最终输出：

```text
prediction: [batch_size]，已经 sigmoid，是点击/正反馈概率
label: [batch_size]
```

## 19. 损失函数

当前 CTR loss 来自 `CTRModel.loss()`。

默认：

```python
self.loss_fn = nn.BCELoss()
```

计算：

```python
loss = self.loss_fn(out_dict['prediction'], out_dict['label'].float())
```

也就是说，模型 forward 输出的 `prediction` 必须是 sigmoid 后的概率。

当前 `CTRLightGCNCTR.forward()` 已经做了：

```python
sigmoid()
```

因此与 `BCELoss` 匹配。

## 20. 当前完整前向传播流程

当前 CTR 模型的一次 forward 可以概括为：

```text
feed_dict
  ├── user_id
  ├── item_id
  ├── c_EEG_data_310_f
  ├── 若干 c_* 情境特征
  └── label

1. 遍历 feed_dict，筛选普通 c_* 情境特征
2. 每个普通情境特征经 Linear(1,16)
3. user_id/item_id 经 LightGCN 得到 u_embed/i_embed
4. c_EEG_data_310_f reshape 为 [batch,62,5]
5. EEG 经 EEGDGCNNEncoder 得到 eeg_emb [batch,16]
6. user/item/eeg/context 分别投影为 64 维 token
7. token gate 调整每个 token 权重
8. self-attention 建模 token 间交互
9. global token cross-attention 汇聚全局样本表示
10. FFN 增强全局表示
11. predictor 输出 logit
12. CTRLightGCNCTR.forward 做 sigmoid
13. BCELoss 用 prediction 和 label 计算损失
```

emb_size = 64

## 22. 当前模型中的遗留或未使用逻辑

### 22.1 combined 变量基本是遗留逻辑

当前 forward 中仍构造：

```python
combined = torch.cat([u_embed, i_embed, eeg_emb], dim=-1)
for feature in self.context_emb:
    combined = torch.cat([combined, feature], dim=-1)
```

但最终预测没有使用 `combined`，因为旧的：

```python
self.fc(combined)
```

已经被注释。

因此，`combined` 当前不影响最终预测。

### 22.2 固定图 EEGGCNEncoder 当前未使用

虽然模型初始化了：

```python
self.eeg_gcn_encoder = EEGGCNEncoder(...)
```

但 forward 中实际使用：

```python
self.eeg_dgcnn_encoder(eeg_feat)
```

因此，固定图 GCN 当前不是主路径。

### 22.3 用户/物品元特征当前未参与融合

虽然 `ContextReader` 可以读入 `u_*` 和 `i_*`，并且 `BaseContextModel` 可以把它们加入 `feed_dict`，但 `LightGCNBase.forward()` 当前只处理：

```text
user_id
item_id
c_* 情境特征
c_EEG_data_310_f
```

没有遍历或编码 `u_*`、`i_*`。

因此，用户和物品元特征当前没有实际进入预测分支。

### 22.4 DGCNN k 值硬编码

当前 DGCNN 初始化为：

```python
EEGDGCNNEncoder(..., k=8)
```

`k=8` 是硬编码，不是命令行参数。

如果后续要做 k 值实验，需要额外把 `dgcnn_k` 加入参数解析并传入模型。

## 23. 当前模型与严格前置 CTR 新数据方案的关系

当前模型仍然直接依赖：

```python
feed_dict['c_EEG_data_310_f']
```

并且使用当前样本的：

```text
c_interest_f
c_immersion_f
c_valence_f
c_arousal_f
c_playrate_f
```

这些字段在严格前置 CTR 新方案中都不再作为当前样本输入。

因此：

> 当前 `CTRLightGCNCTR` 不能直接用于新的 `EEGsvRec_eeg_strict_prectr` 数据集。

原因是新数据集中没有当前样本：

```text
c_EEG_data_310_f
c_interest_f
c_immersion_f
c_valence_f
c_arousal_f
c_playrate_f
```

而是变成了历史序列字段：

```text
history_item_id
history_eeg_310
history_interest
history_immersion
history_valence
history_arousal
history_length
```

后续如果要适配新方案，需要重新设计模型结构，让模型处理历史序列，而不是读取当前样本 EEG。

## 24. 一句话总结

当前 `CTRLightGCN.py` 中的初始版核心模型可以概括为：用 LightGCN 从 `user_id` 和 `item_id` 学习协同过滤表示，用 DGCNN 将当前样本 310 维 EEG 编码成 16 维表示，用 `Linear(1,16)` 编码筛选后的当前情境特征，再把 user、item、EEG、context 表示统一投影为 token，通过 token gate、自注意力、global token cross-attention 和 FFN 融合，最终用 BCE 训练 CTR 点击概率预测。
