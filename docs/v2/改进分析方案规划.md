先给出最重要的结论：

> 目前项目的主要瓶颈不是 EEG 编码器不够复杂，而是评价指标、冷启动假设、数据组织和模型归纳偏置不匹配。现在继续堆 DGCNN、Transformer 或 attention，很可能只会继续过拟合，而不会可靠提升真实推荐能力。

我重新分析了本地数据和预测结果，发现了一些会改变整个优化方向的事实。

## 一、当前结果应该重新解释

### 1. Global AUC 掩盖了用户内排序能力

本机 H5 结果：

| 指标 | 数值 |
|---|---:|
| Global AUC | 0.7762 |
| 用户 Macro AUC | 0.5629 |
| 加权 GAUC | 0.5555 |

这意味着模型主要学会了“哪些用户总体更容易点赞”，但对“同一用户更喜欢哪个视频”的判断能力只略高于随机。

这不是一个小问题。推荐系统真正需要的是用户内部候选排序，而 Global AUC 会把不同用户之间的点赞率差异也算作模型能力。

当前 30 个用户的训练点赞率范围约为 0.088～0.699，仅凭用户身份就能得到约 0.73 的 Global AUC。

因此今后必须：

- GAUC/用户 Macro AUC 作为主指标。
- Global AUC 降为辅助指标。
- 同时报告 LogLoss、Brier Score、ECE。
- 按用户做 cluster bootstrap 置信区间。

### 2. 简单模型已经超过 H5 的 Global AUC

我使用：

- 用户 ID
- 历史点赞率与最近窗口点赞率
- 用户元特征
- 当前视频元特征
- 视频类型

训练了一个 L2 Logistic Regression。

结果：

| 模型 | Dev AUC | Test AUC |
|---|---:|---:|
| H5 | 0.7642 | 0.7762 |
| Logistic Regression | 0.7468 | 0.7881 |

两者差异的初步 bootstrap 区间跨过 0，不能说 Logistic 显著更好；但它足以证明：

> 当前深度模型尚未建立相对于强简单基线的明确优势。

推荐系统研究中复杂模型输给简单基线并不少见，因此可靠基线和统一评估往往比继续增加结构更重要。[相关基线评估研究](https://arxiv.org/abs/1905.01395)

### 3. 当前实际上是强冷启动内容推荐任务

实测：

| 数据集 | 候选 item 未在 train 出现 |
|---|---:|
| Dev | 89.6% |
| Test | 90.6% |

而且 train/dev/test 中没有重复的用户–item 对。

但是当前模型仍使用 `item_id embedding`：

```python
self.item_embedding = nn.Embedding(self.item_num, self.emb_size)
```

对于 90% 的测试 item，这些 embedding 从未被训练，是随机向量。历史序列中来自 dev/test 的新 item 同样使用未训练 embedding。

这是当前模型最明显的结构错误之一。

## 二、必须首先重建评价协议

当前文档反复依据 test AUC 选择模型、融合方式和超参数，因此现有 test 已经实质上变成验证集。H5 的 0.7789 不再是完全独立的最终泛化指标。

建议建立三个分开的评价任务。

### 协议 A：已知用户的视频播放前点赞预测

回答：

> 对已经有历史记录的用户，能否在下一个视频播放前预测他是否会点赞？

采用按用户或 session 的 rolling-origin 时间验证：

```text
过去 → train
稍后 → validation
未来 → locked test
```

测试历史可以包含测试时刻之前已经发生的点赞、观看行为、MAES 和 EEG。本项目明确假设每个视频结束后，其 MAES 与 EEG 都能在下一个视频播放前立即获得，因此同一 session 内前序视频的这些历史信息也可以合法使用。这是“在线逐步获得反馈”的 prequential 场景，任何当前视频或未来视频的后验信息仍然禁止使用。

### 协议 B：新用户泛化

采用：

- Leave-One-Subject-Out，或
- GroupKFold，以 user_id 分组。

这个协议用于判断 EEG 编码学到的是可泛化认知状态，还是仅仅识别出了被试身份。

### 协议 C：新物品泛化

保持当前冷 item 设置，但：

- 不允许使用未训练 item ID embedding。
- 依靠视频内容和元特征表示 item。
- 单独报告 seen-item 与 unseen-item 指标。

最终 test 必须一次性锁定。所有模型、超参数和特征选择只能看 validation。

## 三、重新审计数据定义

本节已经结合数据集论文、官方 EEG 特征处理代码、原始 `data(eeg).csv`、两份 meta 文件以及 strict 派生代码完成核验。以下结论作为后续数据改造和建模的正式口径。

### 1. label、样本和任务定义已经确认

`label` 是用户观看视频过程中是否按下“点赞”按钮：

- `label=1`：真实点赞。
- `label=0`：视频已经曝光并被观看，但用户没有点赞。
- 负样本不是人工负采样，也不是由观看完成率或问卷评分阈值生成。
- 每条交互都对应一次真实视频观看，并具有相应的观看行为、MAES 和 EEG。

论文原始数据包含 3,657 条交互。当前 `data(eeg).csv` 包含 3,558 条交互；少掉的 99 条已经确认是因为对应 item 缺少 `item_meta` 而删除。当前数据包含 30 个用户、2,597 个视频、1,112 条点赞记录，整体点赞率约为 31.25%。

本项目的最终任务正式定义为：

> 在候选视频开始播放之前，基于当时已经可获得的用户信息、候选视频信息和历史交互，预测用户是否会点赞该视频。

因此它不是“是否点击进入视频”的传统 CTR，也不是观看完成后的反馈识别。更准确的描述是“给定曝光条件下的视频播放前点赞概率预测”。代码中的 CTR 命名可以暂时保留，但论文、实验表格和结论必须明确这一任务语义。

### 2. 预测时点的特征可用性已经确认

预测视频 `t` 时，可以使用：

- 用户 ID、性别、年龄、短视频使用年限等静态用户信息。
- 候选视频 `t` 的 ID、静态音视频内容特征、视频来源类型，以及推荐前已经确定的 session mode、顺序和时间信息。
- 视频 `t-1` 及更早历史中的 item、点赞、观看行为、MAES、EEG、时间间隔和 session 信息。

本项目明确采用以下系统假设：用户佩戴 EEG 设备；每个视频结束后，该视频的 EEG 特征和 MAES 都能在下一个视频播放前立即获得。因此，同一 session 内前序视频的 EEG 和 MAES 属于合法历史特征。

预测视频 `t` 时，禁止使用：

- 视频 `t` 的 EEG。
- 视频 `t` 的 MAES。
- 视频 `t` 的观看时长、播放比例、结束时间和点赞结果。
- 视频 `t+1` 及之后的任何信息。

现有 strict 派生数据把当前后验字段移除、只把它们放入后续样本的历史，符合上述核心时间因果关系。`c_session_mode_c`、`c_session_id_c`、`c_video_order_f` 本身不是后验信息，不应一概删除；应保留它们用于 session 边界、顺序、时间间隔和实验模式建模，但不建议把 session ID 当作可泛化的普通类别 ID 强记忆。

### 3. user_meta 与 item_meta 的含义已经澄清

`u_usage_f` 的官方含义是用户已经使用短视频的年限，而不是当前使用强度、累计使用次数或基于全周期行为计算的统计量。它是实验前已经存在的静态用户属性，不构成时间穿越。该字段可以按有序连续值处理，同时建议与类别 embedding 做消融比较。

`i_count_f` 也不是平台播放量，而是视频帧数。根据 `视频总时长≈c_view_duration_f/c_playrate_f` 反推，`i_count_f/视频总时长` 的中位数约为 30.26，且 `i_count_f` 与反推视频时长的相关系数约为 0.993，符合视频帧率特征。它属于推荐前可知的静态视频内容属性，不构成未来统计泄漏。建议将其改名为 `i_frame_count_f`，或者结合帧率转换为更直观的视频总时长。

当前 `item_meta.csv` 的其余字段主要是从视频本身离线提取的音频节奏、分辨率、亮度、对比度、清晰度、颜色和变化量特征，也属于推荐前可用的静态内容特征。此前针对 `i_count_f` 和 `u_usage_f` 的未来信息怀疑现已撤销。

### 4. 310 维 EEG 的语义、顺序和生成方式已经确认

每次交互的 EEG 特征原始形状为 `[62,5]`：62 个电极，每个电极 5 个频带特征。频带顺序固定为：

```text
delta  0.5-4 Hz
theta  4-8 Hz
alpha  8-13 Hz
beta   13-30 Hz
gamma  25-50 Hz
```

官方定义中 beta 与 gamma 在 25-30 Hz 存在重叠，应在实验记录中如实保留，不能擅自按互斥频带重新解释。

电极顺序固定为：

```text
FP1, FPZ, FP2, AF3, AF4, F7, F5, F3, F1, FZ, F2, F4, F6, F8,
FT7, FC5, FC3, FC1, FCZ, FC2, FC4, FC6, FT8, T7, C5, C3, C1,
CZ, C2, C4, C6, T8, TP7, CP5, CP3, CP1, CPZ, CP2, CP4, CP6,
TP8, P7, P5, P3, P1, PZ, P2, P4, P6, P8, PO7, PO5, PO3, POZ,
PO4, PO6, PO8, CB1, O1, OZ, O2, CB2
```

310 维 CSV 向量采用“电极优先、频带次级”的展平顺序：

```text
FP1-delta, FP1-theta, FP1-alpha, FP1-beta, FP1-gamma,
FPZ-delta, FPZ-theta, ...,
CB2-delta, CB2-theta, CB2-alpha, CB2-beta, CB2-gamma
```

即 `flat_index = electrode_index * 5 + band_index`。因此当前模型把最后一维 reshape 为 `[62,5]` 是正确的。

官方特征生成流程是：对每次观看切出 EEG，最长取前 60 秒；按完整 1 秒窗口对每个电极依次计算五个频带的 DE/对数频带功率；对每名参与者全部秒级特征逐维进行 Min-Max 归一化；最后对同一次视频的所有秒取算术平均，得到 `[62,5]`。已经通过秒级 JSON、官方平均 JSON 和 `data(eeg).csv` 逐值验证，三者完全一致。

论文还描述了 baseline correction、M1/M2 平均重参考、0.5-50 Hz 滤波和伪迹去除，但当前可见的资源脚本没有显式执行这些上游步骤，可能以已经清洗的 CNT 为输入，或未包含完整上游脚本。这不影响当前项目使用官方发布的秒级 DE 和 310 维平均特征；但在获得完整上游流程前，不能声称已经从最原始 EEG 完整复现论文预处理。

官方平均特征在数据集发布前使用了参与者全周期秒级 EEG 拟合 Min-Max。按照当前项目决策，这一问题暂时忽略，继续把官方 310 维平均特征视为给定输入，不列为当前数据重建任务；但应在实验限制中保留记录，不能将其误写为项目自行完成的 train-only 预处理。

### 5. 项目新增的 EEG 归一化仍需修正重复计权

当前项目的第二阶段 EEG mean/std 是通过 train 中每一行的完整累计历史统计的。同一个早期 EEG 会在后续许多样本中反复出现，因此被重复计权。

实测 train 中只有约 2,457 条不同的有效历史 EEG 事件，但当前统计累计了 105,621 个 history step，平均每条事件被重复计权约 43 次，而且越早发生的事件权重越大。

应改为：

- 直接从原始事件表确定训练期事件，每条 EEG 只统计一次。
- 项目新增的第二阶段归一化统计只基于 train。
- 对 62 个电极 × 5 个频带的每一维保留独立统计量。
- 同时实验 global、subject-wise、session-wise 和 residual normalization。
- padding 位置不能参与统计。

EEG 存在明显的被试脑电“签名”，跨被试研究已经表明 participant-based normalization 会显著影响结果。[Stratified Normalization 原始研究](https://www.frontiersin.org/journals/neuroscience/articles/10.3389/fnins.2021.626277/full)

### 6. 不再把完整累计历史重复写进每行 CSV

当前 CSV 达到 1.3 GB，是因为历史被平方级重复存储。

建议改成事件表：

```text
event_id
user_id
item_id
timestamp
label
eeg[310]
maes[4]
view_duration
playrate
session_mode
session_id
video_order
```

Dataset 在运行时根据索引动态截取历史。这样可以：

- 避免 EEG 重复存储。
- 避免归一化重复计权。
- 更容易做不同历史窗口。
- 更容易进行 session/rolling split。
- Reader 缓存从数百 MB 降到合理规模。
- 能够在 Dataset 中严格按照预测时点，把当前事件的后验字段排除，并把它们提供给下一条样本。

### 7. 当前生产输入已经齐备，但数据生产链仍应统一

`EEGsvRec_eeg` 目录现在已经同时具备：

- 清洗后的完整事件文件 `data(eeg).csv`，共 3,558 条交互。
- 旧版 `train.csv`、`dev.csv`、`test.csv`，分别包含 2,504、358、696 条交互。
- 原始 `user_meta.csv` 和 `item_meta.csv`。

旧版三份交互合并后，在全部 16 个字段上与 `data(eeg).csv` 的 3,558 条记录完全一致，仅将 `start_time` 改名为 `time`。源目录中的两份 meta 与 strict 目录中的副本 SHA-256 完全一致；30 个交互用户均有 user_meta，2,597 个交互 item 均有 item_meta，item_meta 另含 6 个当前交互未使用的 item，不影响构建。

因此，当前 `build_strict_prectr_dataset.py` 所需输入已经完整，可以重新生成 strict 的 train/dev/test、两份 meta 副本和数据样例。它会合并旧版三份交互，按用户和 `time` 重新排序，再使用当前配额算法划分为 2,487/355/716。随后仍需单独运行 `build_normalization_stats.py` 重建归一化统计，并重新生成 Reader 缓存。旧版三分与 strict 三分包含相同的事件全集，但有 87 条事件的 phase 不同，这是排序和整数配额规则不同造成的。

旧版三份文件本身不能直接作为最终评估切分。它们按用户原始行顺序先取 `ceil(70%)` 为 train，再从剩余部分取 `ceil(33%)` 为 dev；原始行顺序存在 68 次用户内时间倒序，其中用户 2 占 66 次，导致旧版 phase 存在时间交叉。strict builder 合并后按时间重排，修复了这一问题。

当前已经可以复现，但同时维护 `data(eeg).csv` 和旧版三份CSV仍会形成两个输入入口，存在以后内容漂移的风险。后续建议将生产链统一为：

```text
data(eeg).csv
+ user_meta.csv
+ item_meta.csv
→ 数据完整性检查与缺失 item_meta 清洗
→ 按用户时间顺序建立事件索引
→ 切分与动态历史读取
```

删除 99 条缺少 `item_meta` 的交互应由正式构建脚本根据 join 结果自动完成，并输出删除条数、item 列表和原因；不再依赖硬编码 ID 列表覆盖原文件。源数据、清洗规则、切分规则和归一化统计都应保存版本及校验摘要。

在构建脚本完成上述统一之前，每次重建至少应先验证：旧版三份CSV的并集与 `data(eeg).csv` 完全一致、两份 meta 无缺失、用户内按时间排序后再切分，避免把旧版 phase 当作可信时间边界直接沿用。

## 四、建议采用的新主模型

我不建议直接上更大的 Transformer。当前只有 2,487 条训练样本，而 H5 已有约 30 万参数，并在 epoch 1 达到峰值，明显是小数据过拟合。

建议新模型暂称 `EEGStateLike-v2`。如果需要兼容现有工程命名，也可以继续沿用 `EEGStateCTR-v2`，但文档中必须注明其预测目标是视频播放前的点赞概率。

### 1. 候选视频使用内容塔，不再依赖 item ID

```text
视频低级元特征
+ 视频类型
+ 预训练视觉 embedding
+ 预训练音频 embedding
→ candidate content embedding
```

如果有原始视频，可以离线提取：

- 图像/关键帧：CLIP embedding。[CLIP 论文](https://arxiv.org/abs/2103.00020)
- 视频动态：VideoMAE embedding。[VideoMAE 论文](https://arxiv.org/abs/2203.12602)
- 音频：AST embedding。[AST 论文](https://arxiv.org/abs/2104.01778)

这些 embedding 先冻结，仅训练一个小投影层。对于当前 90% 冷 item，这通常比 item ID embedding 更合理。

历史 item 也必须使用相同内容编码器，而不是随机 ID embedding。

### 2. 显式分离长期用户偏置与用户内偏好

推荐使用：

```text
logit =
    global_bias
  + regularized_user_bias
  + user_meta_score
  + candidate_content_score
  + dynamic_history_candidate_score
```

这样可以区分：

- 用户本身是否容易点赞。
- 视频内容是否普遍受欢迎。
- 当前用户状态与候选视频是否匹配。

否则模型很容易只靠 user embedding 刷高 Global AUC。

### 3. 历史模型先用小型 time-aware GRU/DIN

每个历史事件：

```text
历史视频内容
+ 历史 label
+ 历史 MAES
+ EEG 状态
+ 时间间隔
+ session/order
```

建议先使用：

- hidden size 16～32 的 GRU；
- 时间衰减；
- 候选感知 DIN attention；
- 最近 10～30 条历史。

DIN 的核心就是根据当前候选 item 选择相关历史，而不是把全部历史压成同一个向量。[DIN 论文](https://arxiv.org/abs/1706.06978)  
DIEN 进一步建模兴趣随时间演化，也与该任务匹配。[DIEN 论文](https://arxiv.org/abs/1809.03672)

当前结果已经显示：历史越长，Global AUC 越高，但用户内 GAUC 反而越低。这表明长历史主要在估计用户总体点赞率，而不是近期兴趣。因此不能再单纯扩大 `history_max`。

### 4. EEG 应作为“状态变化”，而不是普通拼接特征

更合理的使用方式是：

```text
EEG_t → state gate / FiLM modulation
              ↓
更新用户在 t+1 时刻的兴趣状态
```

即 EEG 描述用户观看完历史视频之后的认知状态，并影响下一次推荐，而不是使用当前候选视频播放期间才会产生的 EEG。本项目假设前一视频的 EEG 和 MAES 均能在下一视频播放前实时获得，因此这种状态更新符合既定推理条件。

可以采用：

```text
eeg_state = EEGEncoder(eeg_t)
gate = sigmoid(W[eeg_state, emotion_t])
history_event = item_content + label_emb + gate * eeg_state
user_state_t = GRU(user_state_{t-1}, history_event)
```

这比现在的“大向量 bilinear 后再 Transformer”更符合因果时间顺序。

## 五、EEG 编码的正确探索顺序

在 2,487 条训练样本下，不应首先追求复杂 EEG Transformer。建议依次实验：

1. PCA/PLS 降维。
2. 频带独立 MLP + channel attention。
3. 脑区聚合：额叶、颞叶、顶叶、枕叶、中央区。
4. 左右半球差异特征。
5. 固定电极拓扑 GCN。
6. 小型可学习邻接图。
7. 数据量足够后才考虑复杂 EEG Transformer。

310 维特征现已确认是 62 个电极 × 5 个频带的交互级平均 DE/对数频带功率特征。五频带顺序为 delta、theta、alpha、beta、gamma，展平方式为电极优先，当前代码 reshape 为 `[62,5]` 是正确的。后续频带独立编码、脑区聚合和固定拓扑 GCN 必须遵循第三节记录的官方电极及频带顺序。

EEG 的关键不是网络名字，而是：

- 基线校正；
- 伪迹处理；
- 通道和频带语义；
- 秒级特征到交互级平均特征的信息损失；
- subject/session normalization；
- 跨被试泛化；
- EEG 是否只是携带用户身份。

## 六、必须做的 EEG 真实性消融

现有 H5 与 C 不是严格 EEG 消融，因为模型结构和融合方式同时发生变化，不能据此得出“EEG 带来 0.02 增益”。

必须在完全相同的 H5/v2 架构下比较：

| 实验 | EEG 输入 |
|---|---|
| E0 | 完全不使用 EEG |
| E1 | 真实 EEG |
| E2 | 用户内随机打乱 EEG 时间顺序 |
| E3 | 跨用户打乱 EEG |
| E4 | 仅用户 EEG 均值 |
| E5 | EEG 去除用户均值后的 residual |
| E6 | 仅情绪，不用 EEG |
| E7 | EEG + 情绪 |
| E8 | EEG 置零但保持相同参数量 |

判断标准：

> 只有真实 EEG 在多种子 GAUC 上稳定超过无 EEG、置零 EEG 和 shuffled EEG，才能证明 EEG 提供了与推荐相关的时序信息。

如果 EEG 与 shuffled EEG 持平，模型使用的主要是被试身份或整体分布，不是真实状态变化。

## 七、训练层面的调整

建议：

- 输出 raw logits，使用 `BCEWithLogitsLoss`，不要先 sigmoid 再 `BCELoss`。
- 使用 AdamW。
- 梯度裁剪 1.0～5.0。
- ReduceLROnPlateau 或 cosine scheduler。
- 每个用户在一个 epoch 中贡献相近权重，避免活跃用户主导。
- 参数量先压到 3万～8万。
- 至少运行 5～10 个随机种子。
- checkpoint 只根据 validation GAUC 保存。
- 记录 mean ± std 和用户级 bootstrap CI。

为了同时优化概率和用户内排序，可使用：

```text
Loss = BCEWithLogits
     + λ × same-user pairwise ranking loss
```

pairwise 部分只在同一用户的正负样本之间计算，直接推动用户内排序，而 BCE 保持概率校准。

## 八、推荐的实验顺序

### 阶段 0：修正评估

- 冻结新 test。
- 加入 GAUC、Macro AUC、Brier、ECE。
- 用户级 bootstrap。
- 建立 warm-user、cold-user、cold-item 三套协议。
- 按 session mode、video type 和 session/order 分层报告，检查模型是否主要学习实验分配策略。

### 阶段 1：强基线

依次运行：

1. Global/User Bias。
2. Logistic Regression。
3. CatBoost/LightGBM。
4. DeepFM/DCNv2。
5. 不含 EEG 的小型 DIN。
6. 不含 EEG 的 time-aware GRU。

如果复杂模型不能超过这些基线，就不进入 EEG 融合阶段。

### 阶段 2：修复冷 item

- 删除或屏蔽 unseen item ID embedding。
- 历史与候选共享内容塔。
- 加入视频预训练 embedding。
- 加入合法的 time gap/session/order 特征。

### 阶段 3：加入 EEG

- subject/session normalization。
- PCA/脑区/频带基线。
- EEG gate 状态更新。
- 严格 shuffled/zero EEG 消融。
- Leave-One-Subject-Out。

### 阶段 4：最后才搜索复杂结构

只有在 EEG 已被证明有独立增益后，再探索：

- 固定拓扑 GCN；
- band/channel attention；
- 域对抗去除 subject identity；
- 自监督 EEG 预训练；
- 轻量 Transformer。

## 最终判断

当前最值得做的并不是 `EEG-DGCN-v2`，而是：

> 建立一个面向冷 item 的内容推荐模型，显式分离用户基础点赞倾向和用户内偏好，再把上一视频及更早历史的 EEG 和 MAES 作为动态用户状态增量注入，在当前视频播放前预测点赞。

短期最可能提升当前 Global AUC 的方法是内容特征 + 用户历史统计模型；最可能提升真实推荐能力的方法则是：

1. 去掉随机 cold-item embedding；
2. 使用候选与历史共享的视频内容表示；
3. 改用 GAUC 驱动训练和选模；
4. 加入时间衰减与 session 信息；
5. 对 EEG 做 subject/session residual normalization；
6. 用严格 shuffled EEG 消融证明 EEG 的真实贡献。

需要接受一种可能性：重新采用正确协议后，AUC 数字可能暂时下降。但如果 GAUC、跨用户泛化和置信区间变得可信，那才是真正的进步。
