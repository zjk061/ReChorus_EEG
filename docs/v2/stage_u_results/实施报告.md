# 阶段 U 实施报告

## 1. 执行结论

阶段 U 首轮性能优先冲刺已经完成 `U0`、`U1`、`U2`、`U3` 和 `U5` 决策。所有实验均使用 `protocol_a_rollv2_cv3` rolling-CV train/dev，未访问 `v2_locked_legacy_test`。

最终冻结的真实 EEG 性能候选为：

```text
U2-profile-gated
```

该候选相对 H2/E0 非 EEG 参考在 rolling-CV dev 上取得稳定提升：

- mean GAUC：`0.611574`
- H2/E0 mean GAUC：`0.602473`
- mean ΔGAUC vs H2/E0：`+0.009101`
- 3/3 folds 相对 H2/E0 为正提升
- 8/9 fold-seed runs 不低于 H2/E0
- LogLoss、Brier、ECE 均优于 H2/E0
- EEG correction、EEG 梯度、zero/shuffle sensitivity 均非零

因此 Gate U 的性能优先筛选通过，`decision.json` 的最终动作是：

```text
freeze_stage_u_candidate::U2-profile-gated
```

## 2. 执行范围

本轮完成范围：

- `U0`：复核 rolling-CV split、H2/E0、G-R real、causal shuffle、zero 锚点。
- `U1`：比较 `U1-profile`、`U1-dynamic`、`U1-profile-dynamic`、`U1-profile-dynamic-film`。
- `U2`：在 U1 最佳 profile 表示上比较 bilinear、FiLM、gated residual、cross-attention。
- `U3`：受控比较 PCA16、小型 Transformer、小型 fixed GCN。
- `U5`：按 Gate U 规则冻结首轮性能候选。

本轮未执行 `U4` stacking/model ensemble。原因是单模型 `U2-profile-gated` 已通过 Gate U，且比 U3 高级编码器更稳；在当前小样本 dev 约束下，继续引入 stacker 会增加 dev 过拟合风险。若后续要追求极限 dev 性能，应先把 stacker 写成只使用 out-of-fold 预测的线性 Logistic/Ridge blender，再单独做确认。

## 4. 工程实现

新增或更新的核心文件：

- `src/baselines/stage_u.py`
- `src/scripts/v2/run_stage_u.py`
- `tests/test_stage_u_eeg_performance.py`

`stage_u.py` 实现了阶段 U 的 EEG profile、dynamic、高级编码器和候选交互结构，真实 EEG 与 `H2_E0`、`causal_shuffle`、`zero` 对照使用同一 fold/dev 协议输出。

`run_stage_u.py` 实现了 `u0`、`u1`、`u2`、`u3`、`u1_u2`、`all` suite，并在每个 run 中落盘 checkpoint、metrics、predictions、control predictions、corrections、training history、config 和环境记录。脚本默认 `--bootstrap 0`，表示首轮快速筛选跳过 paired bootstrap CI。

## 5. 解释边界

本轮结论是：

> 真实历史 EEG 已被模型有效利用，并在 rolling-CV dev 上相对 H2/E0 提升了性能。

但本轮不能表述为：

> 已证明 EEG 正确时间顺序具有独立认知增益。

原因有两点：

- 本轮为了完成首轮筛选使用 `--bootstrap 0`，未生成 paired user-cluster bootstrap CI。
- `temporal_independent_gain_proven=false`；虽然 `U2-profile-gated` 的 mean GAUC 高于 causal shuffle，但还没有完成针对该冻结候选的显著性确认。

因此最终报告应采用降级解释口径：`U2-profile-gated` 是性能优先 EEG 候选，证明的是 EEG 分布/状态信息改善预测；正确时间顺序独立贡献仍待确认。

## 6. 下一步

建议下一步不要继续开放新结构搜索，而是围绕冻结候选做确认：

1. 对 `U2-profile-gated` 补做 targeted paired user-cluster bootstrap，比较 real vs `H2_E0`、real vs `zero`、real vs `causal_shuffle`。
2. 如时间允许，补 5 seeds 确认，目标是至少 10/15 runs 不低于 H2/E0。
3. 冻结 F 阶段候选清单：证据优先 H2、性能优先 `U2-profile-gated`、zero、causal shuffle。
4. 只有用户明确批准后，才能进入 F2 的一次性 `v2_locked_legacy_test` 评估。
