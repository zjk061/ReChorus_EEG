# EEG-SVRec v2 项目完整执行方案

## 1. 文档用途

本文档是项目后续开发、实验和决策的唯一执行路线图。`改进分析方案规划.md` 负责解释“为什么要改”，本文负责规定“先做什么、改哪些文件、产出什么、如何验收、何时停止”。

后续讨论统一使用本文任务编号，例如：

```text
D1：建立唯一数据源
E2：实现 GAUC 与用户级 bootstrap
B3：训练 Logistic Regression 强基线
M2：建立共享内容塔
G4：完成 EEG shuffled 消融
U1：构造 EEG profile/dynamic/candidate-interaction 三通路
```

任何会改变任务定义、数据切分、主指标或 locked test 的决定，都必须先更新本文，再修改代码或运行正式实验。

## 2. 已冻结的项目定义

### 2.1 预测任务

最终任务固定为：

> 在候选视频开始播放前，利用当时已经可获得的信息，预测用户是否会点赞该视频。

`label=1` 表示真实点赞，`label=0` 表示视频已曝光并被观看但没有点赞。负样本不是人工采样。

### 2.2 推理时可用信息

预测视频 `t` 时允许使用：

- 用户静态信息：用户 ID、性别、年龄、短视频使用年限。
- 当前候选视频的静态内容特征、视频来源类型及推荐前已确定的 session 上下文。
- 视频 `t-1` 及更早历史中的 item、点赞、观看行为、MAES、EEG、时间间隔、session 和顺序信息。

系统假设用户佩戴 EEG 设备，并且每看完一个视频就能在下一视频播放前立即获得该视频的 EEG 和 MAES。因此，同一 session 内前序视频的 EEG 和 MAES 可以作为历史输入。

预测视频 `t` 时禁止使用：

- 视频 `t` 的 EEG、MAES、观看时长、播放比例、结束时间和点赞结果。
- 视频 `t+1` 及之后的任何信息。

### 2.3 当前明确暂不处理的事项

- 官方310维平均EEG在发布前使用参与者全周期秒级特征拟合 Min-Max 的问题，当前按用户要求暂时忽略。
- 不重新定义官方五频带范围；beta 与 gamma 的25–30 Hz重叠按官方数据保留。
- 不在基础评估、数据和强基线完成前继续扩大 DGCNN、Transformer 或融合模块。
- 不删除或覆盖 `EEG_DGCN_v1.py`、现有 strict 数据和历史实验脚本；v2 使用新文件和新目录开发。

## 3. 总目标与成功标准

项目目标不是单独提高一次 Global AUC，而是建立可信、可复现、对冷 item 有效，并在真实使用 EEG 脑电特征的前提下尽可能提高视频播放前点赞预测性能。

**用户目标更新（2026-07-06）：性能优先且 EEG 必须进入正式主线。**

- 正式候选模型必须真实使用严格历史 EEG；仅保留一个输出恒零或对预测无敏感性的 EEG 分支不算使用 EEG。
- 当前阶段不再把“真实 EEG 必须击败 causal shuffle”作为进入下一轮开发的唯一前置条件；causal shuffle 继续作为真实性和解释对照，最终报告必须如实披露。
- 若 EEG 提升主要来自用户/会话分布信息，而非正确时间顺序，也可以作为性能优先候选进入后续确认，但结论必须写成“EEG 分布/状态特征改善预测”，不得宣称已证明 EEG 时序认知增益。
- locked test 规则不变：阶段 F 前不得访问 `v2_locked_legacy_test`，所有选择仍只基于 `protocol_a_rollv2_cv3` 的 train/dev。

### 3.1 主指标

模型选择和早停主指标：

1. GAUC：按用户样本量加权的用户内 AUC。
2. Macro User AUC：每个有效用户 AUC 的算术平均。

模型好坏从现在开始只按 AUC 类核心指标判断：

- GAUC：主指标，优先级最高。
- Macro User AUC：用户级补充主指标。
- Global AUC：整体排序能力补充指标。

记录指标：

- LogLoss。
- Brier Score。
- ECE。
- 用户级 bootstrap 置信区间。
- seen-item、unseen-item、session mode、video type 分层指标。

LogLoss、Brier、ECE、ACC 和 F1 只作为审计、校准与阈值相关参考，不作为模型晋级依据。

### 3.2 最终模型晋级条件

证据优先路线下，最终候选模型至少满足：

- 在完全相同协议下，5个随机种子的平均 GAUC 高于所有强基线。
- 至少4/5个种子优于最佳非EEG基线，且结果没有依赖单一异常种子。
- unseen-item 子集没有因随机 item embedding 造成明显退化。
- Macro User AUC 和 Global AUC 不与 GAUC 结论发生严重冲突；若冲突，优先按 GAUC 判断并如实报告分歧。
- 真实 EEG 稳定优于无 EEG、零 EEG 和用户内 shuffled EEG；否则不得宣称 EEG 有效。
- 所有正式结果可由固定配置、数据版本和随机种子复现。

理想证据是用户级 cluster bootstrap 的 `ΔGAUC` 95%置信区间下界大于0。若受小样本限制区间仍跨0，必须如实报告不确定性，不得只依据单次最高值下结论。

### 3.3 性能优先 EEG 候选晋级条件

在当前用户目标下，阶段 U 的性能优先 EEG 候选可以不满足“击败 causal shuffle”这一证明性条件，但必须至少满足：

- 真实 EEG 路径相对 H2/E0 无 EEG 参考有可复现的 GAUC 改进，首轮目标为 mean GAUC 提升不低于 `0.005`。
- EEG 分支对输出有可测影响：zero/shuffle 替换后预测发生非数值噪声级变化，EEG 分支梯度、修正幅度和 permutation sensitivity 均需落盘。
- 至少 2/3 rolling folds 有提升；五种子确认时建议至少 10/15 runs 不低于 H2/E0。
- LogLoss、Brier、ECE 继续记录，但不阻断晋级；若 GAUC 提升伴随校准明显恶化，只在报告中标注校准风险。
- 必须继续报告 H2/E0、zero、causal shuffle 和必要时的新用户/跨用户验证。若真实 EEG 不优于 shuffle，结论只能写为“EEG 被有效利用并改善性能，但正确时序独立贡献未获证明”。

### 3.4 AUC 0.8 及格线

从 2026-07-06 起，项目最终可接受标准提高为：AUC 类核心指标至少达到 `0.8+`，优先看 GAUC，其次看 Macro User AUC 和 Global AUC。当前最佳 `V1-profile-dynamic-gated_cross_attention` 的 GAUC 为 `0.616020`，Macro User AUC 为 `0.619353`，Global AUC 为 `0.654840`，因此它只是“已证明 EEG 路径能带来增益的阶段性候选”，不是最终合格模型。

执行含义：

- `0.8+` 是最终及格线，不是每一轮开发 Gate；否则当前所有模型都会被直接判失败，无法迭代。
- 阶段晋级仍按 AUC-only 增量执行：只要候选稳定超过当前 AUC 冠军，就继续保留并向 `0.8+` 推进。
- 下一阶段必须先做 `0.8` 可达性诊断：判断低 AUC 来自模型能力不足、数据标签噪声、用户内有效正负样本过少、rolling-CV 分布漂移，还是当前协议下理论上限偏低。
- 若 train/dev 严格协议下的强上限诊断也远低于 `0.8`，必须先修数据、任务定义或切分协议解释，不得只靠盲目扩大模型。

构建器必须：

### D2. 改为事件表加动态历史

v2不再把完整累计历史写入每行CSV。事件表至少保留：

```text
event_id, user_id, item_id, start_time, end_time, label,
view_duration, playrate, session_mode, session_id, video_order,
video_type, interest, immersion, valence, arousal, eeg_310
```

Dataset 根据 `event_id` 和用户时间索引动态生成当前时点以前的历史。建议新增：

```text
src/helpers/EEGStateLikeReader.py
```

Reader/Dataset 必须保证：

- 当前样本后验字段不进入当前输入。
- 当前样本的 EEG、MAES、label 和观看行为只会从下一条事件开始成为历史。
- history 截断取最近 `N` 条，而不是最早 `N` 条。
- padding 不参与归一化、池化、attention或统计。
- event_id 在所有产物中保持稳定。

### D3. 补充时间和session特征

构建并保留：

- 与上一事件的时间间隔及其 `log1p` 版本。
- 是否进入新 session。
- 当前 session 内位置与全实验位置。
- session mode、video type。
- 历史观看时长和playrate。

`session_id` 主要用于边界和顺序，不默认作为普通 embedding 强记忆。

### D4. 修复项目新增的EEG归一化

重写 `build_normalization_stats.py` 或新增v2版本：

- 不再遍历每行累计 `history_eeg_310`。
- 310维独立统计 mean/std。
- 输出实际唯一EEG事件数，预期约2457，而不是105621。
- meta连续特征只使用训练中可见用户/item拟合统计量。
- MAES继续使用固定 `(x-1)/4`，避免dev/test统计。

至少支持并记录以下策略，首轮只实现 `global_train_zscore`：

```text

session_residual
```

## 7. 阶段 E：重建评价和test隔离

### E1. 修复CTRRunner基础问题

修改或新建v2 Runner，优先建议新建：

```text
src/helpers/LikePredictionRunner.py
```

必须修复当前 `CTRRunner` 在显式传入 `--main_metric` 时仍引用 `self.main_metric` 的错误，应正确读取 `args.main_metric`。

训练脚本必须支持：

- `--main_metric GAUC`。
- `--eval_test 0`，开发训练结束后不自动评估test。
- 只按dev主指标保存checkpoint和早停。
- `--test_epoch -1` 作为强制默认值。

### E2. 实现完整指标

新增统一评价模块，例如：

```text
src/utils/like_metrics.py
```

实现：

- Global AUC。
- GAUC。
- Macro User AUC。
- LogLoss。
- Brier Score。
- ECE，固定bin规则并记录bin数。
- ACC/F1，仅辅助。

GAUC和Macro AUC只统计同时包含正负样本的用户，并同时报告：

- 有效用户数。
- 被排除用户数及原因。
- GAUC权重定义。

### E3. 用户级cluster bootstrap

以用户为抽样单位有放回抽样，而不是逐样本bootstrap。固定随机种子，默认1000或2000次，输出：

- 单模型指标95%置信区间。
- 两模型配对 `ΔGAUC/ΔAUC/ΔLogLoss` 置信区间。
- bootstrap失败次数和有效次数。

### E4. 分层评估与预测落盘

每次评估保存：

```text
event_id,user_id,item_id,time,label,prediction,
seen_item,session_mode,video_type,history_length
```

自动生成：

- seen-item/unseen-item指标。
- 各session mode、video type指标。
- 按历史长度分桶指标。
- 每用户 AUC、样本数、点赞率。

### E5. 评价器单元测试

使用人工小数组验证：

- AUC、GAUC、Macro AUC手算一致。
- 单类别用户处理正确。
- 样本顺序变化不影响指标。
- bootstrap以用户簇为单位。
- ECE边界值0和1处理正确。
- 显式 `--main_metric GAUC` 能控制早停。

```text
logit = global_bias
```

## 10. 阶段 G：证明EEG是否真正有效

### G1. 先做简单EEG编码器

按顺序实现：

1. PCA/PLS降维基线。
2. 310维小型MLP。
3. 五频带独立MLP + channel attention。
4. 脑区聚合与左右半球差异。
5. 固定电极拓扑GCN。
6. 小型可学习邻接图。

首轮禁止直接上大型EEG Transformer。

### G2. EEG作为历史状态增量

推荐结构：

```text
eeg_state_t = EEGEncoder(eeg_t)
maes_state_t = MAESEncoder(maes_t)
gate_t = sigmoid(W[eeg_state_t, maes_state_t])
history_event_t = base_event_t + gate_t * eeg_state_t
user_state_{t+1} = GRU(user_state_t, history_event_t)
```

EEG只更新下一时刻用户状态，不允许连接当前候选视频的当前EEG。

### G3. 归一化消融

在相同模型上比较：

- global train z-score。
- subject train z-score。
- subject residual。
- session residual。

必须使用唯一训练事件统计，不能恢复累计历史重复计权。

### G4. EEG真实性消融矩阵

完全相同架构、参数规模和训练协议下运行：

| ID | 输入 |
|---|---|
| E0 | 无EEG |
| E1 | 真实EEG |
| E2 | 用户内打乱时间顺序的EEG |
| E3 | 跨用户打乱EEG |
| E4 | 仅用户EEG均值 |
| E5 | 去除用户均值后的EEG residual |
| E6 | 仅MAES |
| E7 | EEG + MAES |
| E8 | EEG置零但保留相同参数路径 |

shuffle映射必须由固定种子生成并保存，确保不同模型重复使用同一扰动。

### G5. 新用户泛化

对关键模型运行LOSO或GroupKFold：

- 无EEG主干。
- 真实EEG。
- shuffled EEG。
- EEG residual。

用于判断EEG是否只编码被试身份。

### Gate G

只有真实EEG在多种子GAUC上稳定优于E0、E2和E8，才能进入复杂EEG结构搜索并在结论中宣称EEG提供了时序增益。若不满足，则保留“EEG无可靠独立增益”的结论，主模型退回最佳非EEG版本。

**实施状态（2026-07-04）：已完成，Gate G 未通过。**

- 在阶段 M-R 选出的 `H2-history-behavior` 非 EEG 主干上实现历史 EEG/MAES 门控状态增量；EEG 只进入严格早于候选的历史事件，当前候选 EEG 无输入路径。
- 小型 EEG 编码、四种训练期归一化、固定可复现 shuffle、E0–E8 同路径真实性消融及新用户 GroupKFold 实现见 `src/models/general/eeg_state_encoder_v2.py`、`src/baselines/stage_g.py` 和 `src/scripts/v2/run_stage_g.py`。
- G4 共完成 3 folds × 9 消融 × 5 seeds = 135 次运行。E0/E1/E2/E8 平均 GAUC 分别为 `0.605686/0.601806/0.596337/0.595104`；E1 相对三者的配对用户簇 ΔGAUC 95% CI 均跨 0，且未满足逐 fold 4/5 种子稳定性规则。
- G3 四种归一化中 global train z-score 的最终 rolling-fold 五种子 GAUC 最高（`0.606919`）；所有统计均只由当前 fold 的唯一训练事件拟合。
- G5 五折新用户结果中 E1/E2/E5/E0 平均 GAUC 为 `0.641785/0.639663/0.638807/0.637923`，E1 与 causal shuffle 差异很小且校准更差，不构成独立时序增益证据。
- 所有配置均记录 `locked_test_accessed=false`；阶段 G、阶段 M 回归及全套 `test_stage_*.py` 均通过。机器可读结果和完整解释见 [`stage_g_results/`](./stage_g_results/)。
- 按停止规则，主模型保留 `H2-history-behavior`，不进入复杂 EEG 图结构或大型 EEG Transformer 的正式搜索。

**用户约束更新（2026-07-04）：EEG 必须保留在正式项目主线。**

- Gate G 的失败结论不撤销，但其含义限定为“已实现的 EEG 均值池化门控方案无可靠增益”，不得外推为“EEG 数据永久无用”。

## 11. 阶段 T：训练、损失和有限搜索

### T1. 改用raw logits

模型forward输出raw logits，训练使用：

```python
BCEWithLogitsLoss
```

评估时再sigmoid。验证新旧损失在相同logit下数值一致，并检查无NaN/Inf。

### T2. 优化器和稳定性

默认：

- AdamW。
- 梯度裁剪1.0或5.0。
- ReduceLROnPlateau或cosine scheduler。
- early stop依据dev GAUC。
- 参数量优先控制在3万–8万，超过时必须说明必要性。

### T3. 用户平衡

比较：

- 普通sample-level BCE。
- 按用户逆样本量加权。
- user-balanced batch sampler。

观察Global AUC、GAUC和校准之间的变化。

### T4. 同用户pairwise损失

在最佳BCE模型后再实验：

```text
Loss = BCEWithLogits + λ × same-user pairwise ranking loss
```

只在同一用户正负样本间构造pair。搜索少量 `λ`，例如0、0.05、0.1、0.2，不进行大规模网格搜索。

### T5. 随机种子和搜索预算

- 开发筛选：3个种子。
- 晋级确认：至少5个种子。
- 最终核心结论：条件允许时10个种子。
- 超参数只在dev/rolling validation搜索。
- 每一阶段只搜索少量有理论依据的参数，禁止在当前test上反复试验。

**实施状态（2026-07-06）：已完成，Gate T 通过为“作出保留/替换决策”，但没有训练优化候选晋级。**

- 阶段 T 严格固定 `band_region + multiscale + bilinear EEG residual` 候选，只比较 scheduler、用户平衡和同用户 pairwise loss；未更换 EEG 表示、融合结构或数据协议。

## 12. 阶段 U：EEG性能优先冲刺

### U0. 重新冻结目标和回归锚点

阶段 U 的唯一目标是：

> 在不泄漏当前/未来信息、不访问 locked test 的前提下，通过真实使用历史 EEG 特征提升 rolling-CV dev 指标性能。

进入 U 阶段前必须先复现并落盘以下锚点：

- `H2-history-behavior` / E0：当前最佳证据优先非 EEG 主干。
- G-R real：`band_region + multiscale + bilinear EEG residual`。
- G-R causal shuffle。
- G-R zero。

若 U0 无法复现 `stage_t_results` 和 `stage_g_recovery_results` 的合理波动范围，停止后续 U 实验，先修复实现或数据入口。

### U1. EEG三通路建模

阶段 U 不再把 EEG 压成单一路径，而是显式拆分为：

1. `EEG-profile`：用户/会话稳定脑电画像，包括历史 EEG rolling mean、rolling std、band/region 均值、左右半球差异、subject/session profile。
2. `EEG-dynamic`：短期状态变化，包括 last、delta、EMA3、EMA10、trend 和时间衰减。
3. `EEG-candidate-interaction`：候选感知交互，让 EEG 改变同一用户面对不同候选内容时的相对分数。

推荐 logit 结构：

```text
logit = H2_base_logit
      + eeg_profile_score
      + eeg_dynamic_score
      + eeg_candidate_interaction_score
```

首轮比较以下配置：

```text
U1-profile
U1-dynamic
U1-profile-dynamic
U1-profile-dynamic-film
```

其中 `U1-profile-dynamic-film` 使用 EEG 状态生成候选内容表示的 scale/shift：

```text
candidate_repr' = gamma(eeg_state) * candidate_repr + beta(eeg_state)
```

### U2. 候选感知交互结构

在 U1 最佳表示上比较少量候选交互，不做无边界搜索：

- low-rank bilinear residual。
- FiLM / feature-wise modulation。
- gated residual adapter。
- 小型 cross-attention；仅允许低维 EEG 状态与候选内容 token 交互。

所有交互结构必须保留 H2 base logit，EEG correction 采用零初始化或小尺度初始化，避免训练初期破坏内容锚点。

### U3. 受控高级 EEG 编码器

阶段 A 的大型无边界搜索仍不开放，但阶段 U 允许在性能优先目标下受控恢复少量高级 EEG 编码器：

1. band/region MLP 增强版。
2. PCA16/PLS + 小型 MLP。
3. 小型 EEG Transformer，输入为多尺度状态后的 band/region 特征，而不是原始 `30 × 310` 序列。
4. 小型 GCN/DGCNN 回归，只比较少量 k 值：`4, 8, 12, 20`；不得恢复大规模 k 网格。

参数量原则上控制在 2万到 8万；超过时必须先说明必要性并记录到实验台账。

### U4. 性能优先集成

小样本下单模型方差较大，阶段 U 允许使用 dev-only、fold 内可复现的集成方法：

- seed ensemble：同一配置多种子平均。
- model ensemble：少量 EEG 候选平均。
- out-of-fold stacking：只用 rolling fold 的 dev 预测训练 Logistic/Ridge meta blender。

stacker 输入可以包括：

```text
H2 prediction
real EEG prediction
EEG-profile prediction
EEG-dynamic prediction
EEG-candidate prediction
prediction deltas
```

stacker 不得读取 locked test，不得使用当前事件后验字段，不得用复杂非线性模型背 dev。

### U5. 晋级与停止规则

首轮预算：

```text
U0 回归锚点：不超过 12 runs
U1 三通路筛选：3 folds × 3 seeds × 4 configs = 36 runs
U2 交互结构筛选：3 folds × 3 seeds × 最多 4 configs = 36 runs
U3 高级编码器筛选：3 folds × 3 seeds × 最多 4 configs = 36 runs
U4 集成确认：基于已落盘预测，必要时补 5 seeds
```

首轮 U 候选晋级条件：

- 相对 H2/E0 mean GAUC 提升不低于 `0.005`。
- 至少 2/3 folds 提升；若进入五种子确认，至少 10/15 runs 不低于 H2/E0。
- LogLoss、Brier、ECE 只记录为校准审计，不作为晋级门槛。
- EEG zero 替换导致预测和指标可测下降；EEG 梯度、correction、permutation sensitivity 均非零。
- causal shuffle 继续报告；若 shuffle 不低于 real EEG，可晋级为性能候选，但最终解释必须降级为“EEG 分布/状态信息有用，时序独立贡献未证明”。

### Gate U

Gate U 不要求证明 EEG 正确时间顺序独立有效；它只要求在当前用户目标下按 AUC 类核心指标作出可复现的性能候选冻结决策：

- 若真实 EEG 候选稳定优于 H2/E0，则冻结最佳 EEG 单模型和必要对照，进入 F 阶段候选审计；校准指标只记录不阻断。
- 若 EEG ensemble 或 stacker 稳定优于单模型，也可作为性能优先候选，但必须同时冻结其所有基模型、种子和 blender 训练规则。
- 若所有 EEG 候选均无法稳定超过 H2/E0，则记录“在当前数据与预算下 EEG 性能冲刺未成功”，由用户在“证据优先 H2”和“强制 EEG 候选”之间做产品取舍；不得通过继续无边界搜索补救。

### V2. 0.8可达性诊断与AUC-only冲高

**新增目标（2026-07-06）：最终及格线为 AUC 类核心指标 `0.8+`。** V2 的第一任务不是直接宣称能靠调参达到 0.8，而是先给出可复现的可达性诊断，同时用现有预测做低成本 AUC 冲高。

V2-A：0.8 可达性诊断。

- 汇总当前冠军、V1 次优、U2 冠军和 H2/E0 的 GAUC、Macro User AUC、Global AUC，计算距离 `0.8` 的缺口。
- 统计 rolling-CV dev 中有效用户数量、正负样本分布、每用户 dev 样本量、全正/全负用户比例，判断 GAUC 是否受小样本用户结构强烈限制。
- 只使用 train/dev 和已落盘预测，不访问 `v2_locked_legacy_test`。
- 产出 `docs/v2/stage_v2_results/reachability_report.json`、`reachability_summary.csv` 和 `实施报告.md`。

V2-B：现有候选的低成本 AUC-only 冲高。

- 使用 `V1-profile-dynamic-gated_cross_attention`、`V1-profile-dynamic-gated` 和 `U2-profile-gated` 的已落盘 rolling-fold ensemble 预测。
- 评估 simple average、加权 average 和 out-of-fold Logistic/Ridge 线性 blender。
- blender 必须按 fold 做 OOF：评估某个 fold 时，只能用其他 dev folds 的预测和标签训练 meta 模型；不得在同一 fold 上训练再评估。
- 若 ensemble/blender 超过当前冠军，则冻结为 V2 候选；若没有超过，则记录“现有候选线性组合无法显著缩小 0.8 缺口”，下一步进入更重的排序学习/特征修复。

V2-C：若 V2-B 未显著提升，下一轮才进入重训练路线。

- 同用户 pairwise/listwise AUC loss 重新设计。
- hard negative mining 和用户内正负配对采样。
- EEG 多尺度特征增强：band/region/asymmetry、profile、dynamic、candidate interaction 的统一表示。
- 更强但仍受控的模型族：轻量 Transformer、固定图 GCN/DGCNN、cross-attention residual scale 搜索。

V2-D：若 V2-C 仍未超过当前冠军，下一轮不继续盲目堆叠同类结构，而先做 fold/user 级失败归因与 0.8 可达性再诊断。

- 对 fold1/fold2/fold3 分别输出模型、H2/E0、zero、shuffle 的用户级 GAUC、样本量、正负样本数、点赞率和 EEG sensitivity。
- 定位 fold2 高点与 fold1/fold3 低点的差异：用户组成、历史长度、session mode、video type、候选 item 分布、hard-negative pair 覆盖率、EEG correction 幅度。
- 建立只用于诊断、不用于晋级的 train/dev oracle/upper-bound 表，判断当前协议下 `0.8` 缺口主要来自模型能力、特征表达、标签噪声、用户内有效样本不足还是 rolling-CV 分布漂移。
- V2-D 不访问 `v2_locked_legacy_test`，不产生可直接晋级的“作弊上限模型”，只产生下一轮 V2-E 的具体修复方向。

V2-E：若 V2-D 确认 `0.8` 无法靠同类重训练/简单选择达到，下一轮只做受控修复，不做无边界大模型搜索。

- loss 修复：围绕 listwise loss、pairwise_weight/cap 搜索、hard-negative 覆盖率和用户样本量加权做小范围预注册实验。
- EEG 表达修复：稳定 fold1/fold3 的 EEG correction，尝试多尺度 band/region/asymmetry 表示、subject/session residual、correction shrinkage 和低样本用户正则。
- 数据/协议解释修复：若诊断上限仍远低于 `0.8`，优先报告当前严格 rolling 协议下的可达性限制，而不是继续堆复杂模型。
- V2-E 的任何模型候选仍必须超过当前正式冠军 GAUC `0.616020` 才能晋级；未达 `0.8+` 不得称为最终合格模型。

V2 Gate：

## 14. 阶段 F：最终确认和报告

### F1. 冻结候选

根据rolling validation选择：

- 最佳简单基线。
- 最佳非EEG模型。
- 最佳真实EEG模型。
- 必要的shuffled/zero消融。

冻结代码、配置、checkpoint规则和种子后，才允许访问 `v2_locked_legacy_test`。

### F2. 一次性locked test

统一运行并报告：

- GAUC、Macro User AUC、Global AUC。
- LogLoss、Brier、ECE。
- 用户级bootstrap CI和模型差值CI。
- seen/unseen item分层。
- session mode、video type、history length分层。
- 5或10种子mean±std。

不得根据locked test结果返回修改超参数。如果发现实现bug，可以修复后整体重跑，但必须在实验台账中记录原因，不能选择性保留更好结果。

### F3. 最终结论规则

- 非EEG模型最好：结论是内容和历史建模有效，EEG尚无可靠独立贡献。
- 真实EEG优于无EEG但不优于shuffle：结论是EEG主要提供用户身份或分布信息。
- 真实EEG稳定优于无EEG和shuffle：可以主张EEG提供时序认知状态增益。
- Global AUC升高但GAUC下降：不视为推荐能力提升。

**当前状态（2026-07-06）：尚未进入 locked test。** 当前 AUC-only 最佳仍为 `V1-profile-dynamic-gated_cross_attention`，但它距离最终 `0.8+` 及格线仍有明显差距。V2-A/V2-B 已确认现有候选线性组合无法接近 `0.8`；V2-C 已确认首轮 pairwise/hard-negative 重训练未超过当前冠军；V2-D 已确认当前模型池的诊断 oracle 也无法接近 `0.8`。当前应进入 V2-E 受控 loss/特征/数据解释修复，任何一次性 locked-test 命令仍需要用户明确批准。

## 16. 风险、停止规则和回退策略

### 16.1 小样本过拟合

表现：最佳epoch过早、种子方差大、train持续提升而dev下降。

措施：减小参数、加强正则、减少历史长度、使用简单模型、多种子和置信区间。不得通过报告单一最佳种子掩盖。

### 16.2 Global AUC假提升

表现：Global AUC提高但GAUC不变或下降。

措施：检查user bias占比、按用户指标和分层结果；模型不得晋级。

### 16.3 冷item随机表示

表现：unseen item仍经过未训练ID embedding。

措施：默认内容塔；ID仅在seen-item消融中使用；增加自动测试阻止随机cold ID进入正式模型。

### 16.4 EEG伪增益

表现：真实EEG与用户内shuffle、用户均值表现相同。

措施：结论降级，使用residual/LOSO验证；不继续堆复杂EEG结构。

### 16.5 数据入口漂移

表现：`data(eeg).csv`与旧版三分并集不一致。

措施：构建立即失败；不自动选择其中一套继续训练。

### 16.6 test再次变成验证集

表现：训练脚本自动打印test，或根据test选择模型。

措施：默认 `eval_test=0`；最终脚本与开发脚本分离；访问记录写入实验台账。

### 16.7 EEG性能优先导致dev过拟合

表现：阶段 U 中 EEG 候选在少数 fold/seed 上大幅提升，但配对用户簇 CI 跨 0、zero/shuffle 敏感性不足，或 stacker 对 dev 预测过度贴合。

措施：所有 U 候选必须保留 H2/E0、zero、causal shuffle 对照和五种子确认；stacker 只能使用 out-of-fold 预测和线性/岭回归类小模型。若提升来自单一 fold、单一 seed 或单一复杂 blender，不晋级。

### 16.8 EEG解释和性能目标混淆

表现：真实 EEG 候选优于 H2/E0，但不优于 causal shuffle，却在报告中被表述为“EEG 时序认知状态有效”。

措施：阶段 U 允许这种候选作为性能优先模型，但结论必须降级为“EEG 分布/状态信息改善性能，正确时间顺序独立贡献未证明”。真实性消融不得删除，不得只报告 real EEG。

### 第十三批：V2-G任务重定义与协议修订试验

进入 V2-G：基于 V2-F 结论，不再把下一轮主线定义为同一 rolling 二分类协议下继续堆模型，而是先做最小可执行的数据/任务/协议修订试验。优先级如下：

1. `session_or_block_local_ranking`：把监督目标从跨长时间 rolling 的二分类偏好，改为同用户同 session/block 内的局部排序或偏好差分，检查 EEG 是否更能解释短时状态下的相对偏好。
2. `multi_task_affective_target`：把 interest、immersion、valence、arousal 作为辅助或中间监督目标，再映射到 like，只用 train/dev 验证是否提升 GAUC、Macro User AUC 和 Global AUC。
3. `larger_per_user_validation_or_grouped_protocol`：构造更厚的 per-user rolling blocks 或更少但每用户样本更充分的验证切片，避免用大量样本数为十几个的用户切片评判模型。

## 19. 完成定义

只有同时满足以下条件，v2项目才算完成：

- 数据构建单源、确定、可校验、可复现。
- 当前后验字段无穿越，历史时点语义正确。
- 训练、选模和最终测试严格分离。
- 强基线完整，模型比较使用同一协议。
- cold item不依赖随机未训练ID表示。
- EEG必须真实参与正式候选；其增益需经过无EEG、零EEG、shuffle和必要的跨用户验证。若性能提升未击败 shuffle，最终报告必须明确区分“性能上利用 EEG”和“证明 EEG 时序独立贡献”。
- 阶段 U 的性能优先候选、证据优先 H2 参考和所有对照均已冻结；若使用 ensemble/stacker，其基模型、种子、预测文件和 blender 规则也必须冻结。
- 正式结果包含多种子、置信区间、校准和分层指标。
- 所有代码、脚本、配置、预测和报告能够由第三方重跑。
