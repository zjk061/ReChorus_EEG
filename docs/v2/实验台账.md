## 2. test 使用规则

1. 训练、早停、阈值选择、特征选择、结构选择和超参数选择只能使用 train/dev。
2. 阶段 P0 到 T/A 的实验不得加载、预测、汇总或查看 `v2_locked_legacy_test`。
3. 阶段 F 之前，结果表中的 `test_*` 必须为空，`test_access` 必须为 `locked_not_accessed`。
4. 阶段 F 只有在代码 commit、数据及 split、特征集、配置、checkpoint 规则和种子列表全部冻结后，才允许一次性访问 locked test。
5. 任何意外 test 访问都必须立即记录为 `accidental_access`，说明时间、命令、人员和影响；相关配置不得再声称由独立 test 确认。
6. v1/H5 行使用 `legacy_used_for_selection`，其 test 指标只作历史参照，不能作为 v2 开发的晋级依据。
7. 阶段 E 应在程序层实现 test 隔离；P0 当前建立的是强制治理规则，不能代替后续代码防护。

## 3. 每次实验的必填信息

实验启动前必须确定：

- `experiment_id`、阶段、模型名和实验目的。
- `data_version`、`split_version` 和 `feature_set`。
- Git commit、完整命令或配置文件路径、随机种子。
- 计划访问的数据 phase；默认只能是 train/dev。

实验完成后必须补齐：

- 状态、参数量、最佳 epoch、总运行时间。
- dev 的 GAUC、Macro User AUC、Global AUC、LogLoss、Brier、ECE。
- checkpoint 和 dev prediction 的路径。
- 失败、异常、偏离预注册配置或意外 test 访问说明。

只有阶段 F 可以补写 `test_*` 与 test prediction。

## 4. experiment_id 规范

使用以下稳定格式：

```text
<stage>_<model>_<feature_set>_<split_version>_s<seed>
```

示例：

```text
B_LR_all_rollv2_s0
M_GRU_content_h20_rollv2_s2
G_EEGGate_real_h20_rollv2_s4
```

experiment_id 一旦产生结果不得复用。配置发生变化时必须使用新 ID，而不是覆盖旧记录。

## 5. 版本字段规范

- `data_version`：描述事件源和派生版本，例如 `strict_prectr_v1`、`event_table_v2`。
- `split_version`：描述固定划分，例如 `legacy_strict_prectr_2487_355_716`、`rollv2_manifest_sha8`。
- `feature_set`：使用简短稳定名称；具体列清单必须在对应配置或实验说明中展开。
- `git_commit`：保存完整 40 位 commit。若工作区不干净，必须额外记录 diff，不允许只写 commit。
- `config_or_command`：优先保存仓库内配置/脚本路径；临时命令必须原样写入实验说明。

## 6. 统一结果表

机器可读表采用 UTF-8 CSV，一行对应一个模型、一个 seed、一个 split。必需字段覆盖执行方案要求，并增加治理字段：

```text
experiment_id,status,stage,model,seed,data_version,split_version,feature_set,
git_commit,params,best_epoch,runtime_seconds,
dev_gauc,dev_macro_auc,dev_auc,dev_logloss,dev_brier,dev_ece,
test_access,test_gauc,test_macro_auc,test_auc,test_logloss,test_brier,test_ece,
checkpoint,prediction_file,config_or_command,notes
```

约束：

- 指标存 0 到 1 之间的原始小数，不存百分数。
- 未计算或被锁定的字段留空，不写 0、`N/A` 或虚构值。
- `status` 使用 `planned`、`running`、`completed`、`failed`、`invalidated`。
- `test_access` 使用 `locked_not_accessed`、`final_access`、`legacy_used_for_selection`、`accidental_access`。
- checkpoint 与 prediction 使用相对仓库根目录的路径。
- 汇总 mean±std 和 bootstrap CI 另建汇总行或报告，不覆盖单 seed 原始行。

## 9. 当前阶段 T 约束

**状态：暂停。** 本节预注册内容保留，但在阶段 G-R 完成前不得启动。

- 冻结数据、rolling folds、`content_only`、30 步行为历史、LR 内容锚点和 hidden size 24。
- 阶段 T 只能优化非 EEG H2 的训练方式；不得恢复 EEG、MAES 或随机 item-ID 路径。
- 默认 H2 是必须保留的配对参考，不允许用新实现悄悄重定义参考模型。
- 开发筛选用 3 seeds，晋级确认用 5 seeds；所有正式比较按用户簇配对。
- 若候选未满足逐 fold 稳定性和 `ΔGAUC` CI 规则，立即回退 H2，不扩大搜索。
- F 阶段一次性 locked-test 访问尚未批准；T 阶段所有结果的 `test_access` 必须继续为 `locked_not_accessed`。

## 10. 当前阶段 G-R 约束

- 正式候选必须真实使用严格历史 EEG；zero 输出或无敏感性的装饰分支不算使用。
- H2 继续作为安全锚点和 E0 证据基线，不得删除或弱化。
- 优先修复 mean pooling、缺少候选交互和高维小样本问题；只允许 PCA/统计编码、last/delta/EMA/trend 和小型候选感知 residual。
- 大型 GCN、DGCNN、Transformer 仍不开放，不得借用户要求扩大为无边界搜索。
- 继续保存 causal shuffle、zero、梯度、修正幅度和 permutation sensitivity 证据。
- 若 EEG 仍未证明独立增益，报告必须明确区分“项目强制使用 EEG”和“统计证据证明 EEG 有效”。
- locked test 继续隔离；详细计划见 `docs/v2/EEG强制使用恢复计划.md`。
